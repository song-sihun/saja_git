## 1. 최신 프론트엔드 아키텍처 이해 및 Next.js의 필요성
*   **컴포넌트 기반 개발:** React, Vue, Angular 등의 최신 기술들은 화면 전체가 아닌 '컴포넌트(조각)' 단위로 구성 요소를 만들어 조립하는 방식으로 작동합니다. 데이터를 반영하거나 특정 부분만 움직이도록 설계할 수 있어 효율적입니다.
*   **SEO 문제 (검색 엔진 노출):** React와 같은 클라이언트 측 렌더링(Client-Side Rendering, CSR) 방식은 요청 시 서버가 빈 페이지를 전송하고 브라우저에서 자바스크립트가 동작하며 화면을 완성합니다. 이 때문에 검색 엔진 크롤러가 콘텐츠가 없는 빈 소스 코드만 읽게 되어 SEO 문제가 발생할 수 있습니다.
*   **Next.js의 역할 (SSR):** Next.js는 이러한 문제를 해결하기 위해 **서버 측 렌더링(Server-Side Rendering, SSR)**을 지원합니다. 서버에서 이미 완성된 HTML 페이지를 클라이언트에게 전달함으로써, 검색 엔진이 콘텐츠가 포함된 완전한 페이지를 읽도록 보장합니다.
*   **컴포넌트 역할 분리:** Next.js 환경에서는 사용자가 정의하는 컴포넌트와서버에서 렌더링되는 컴포넌트를 나누어 작업할 수 있습니다.

## 2. 개발 과정과 배포 환경에 대한 이해 (DevOps 관점)
*   **백엔드 개발자의 책임 영역:** 백엔드 개발자라면 애플리케이션이 실제로 동작하는 **'배포(Deployment)' 및 '운영(Operation)'** 단계까지의 전반적인 프로세스를 이해하고 있어야 합니다. 제작으로 끝나는 것이 아니라 실제 서버에 배포하여 운영할 수 있는 지식 기반을 갖추는 것이 중요합니다.
*   **필수 개발 역량:** 프론트엔드 개발자로서도 관리자 페이지 등 내부적으로 사용되는 시스템의 동작 방식(프론트엔드 구조)을 이해하는 것이 좋습니다.
*   **배포 프로세스 자동화 (CI/CD):** 애플리케이션이 지속적으로 업데이트되고 통합되어 배포될 때, 이 모든 과정을 자동으로 처리할 수 있는 파이프라인 구축 및 운영 방법을 학습해야 합니다.

## 3. 컨테이너 기술을 통한 시스템 효율화 (Docker와 Linux)
*   **운영체제(OS) 환경의 필요성:** 안정적으로 애플리케이션을 배포하고 운영하려면, 개발자가 만든 앱을 구동할 수 있는 **통일된 OS 기반 환경**이 필수적입니다. 특히 대규모 서비스는 여러 서버가 동시에 동작해야 합니다.
*   **도커 (Docker)의 등장 배경 및 정의:**
    *   **목표:** 애플리케이션 실행 환경을 격리하고 이식성(Portability)을 확보하여, '내 컴퓨터에서는 되는데 서버에서는 안 되는' 문제를 해결합니다.
    *   **원리:** 도커는 **컨테이너 기반의 가상화 기술**을 제공하며, 하나의 컨테이너를 독립적인 컴퓨터 환경처럼 사용하게 합니다. (물리적 컴퓨터 대여 개념)
    *   **Image와 Container:** 개발자가 원하는 상태(OS + 소프트웨어 스택 등)를 담은 '이미지(Image)'를 만든 후, 이 이미지를 기반으로 실제 동작하는 공간인 '컨테이너(Container)'가 실행됩니다.
*   **도커의 장점 (VM과의 비교):**
    *   **경량화 및 속도:** 도커는 호스트 OS의 커널을 공유하여 사용하므로, 완전히 독립된 운영체제 전체를 가상화하는 전통적인 **가상 머신(Virtual Machine, VM)**보다 훨씬 빠르고 가볍습니다.
    *   **격리성:** 각 컨테이너가 독립적인 환경에서 실행되므로, 한 컨테이너의 문제 발생이 다른 시스템에 영향을 주지 않습니다.
    *   **확장성 및 배포 용이성:** 하나의 이미지를 만들어 여러 대의 서버(100대 이상)에 동일한 환경으로 빠르게 복제하고 배포할 수 있습니다. (Scale-Out 용이)
*   **학습 목표 및 향후 계획:**
    *   도커를 이용하여 **Amazon Linux**와 같은 리눅스 운영체제를 컨테이너로 구축하고 활용하는 실습을 진행합니다.
    *   실습의 궁극적인 목표는 개발한 애플리케이션을 도커 환경으로 구성하여, 최종적으로 AWS(클라우드 서비스)에 배포 및 운영까지 경험해 보는 것입니다.

3. 데이터 영속성 확보: 볼륨과 마운트 개념 (Data Persistence)
4. 다중 서비스 환경 구성: Docker Compose 활용

---

## 1. 도커 이미지 이해 및 다운로드
도커 컨테이너를 실행하기 위해서는 먼저 해당 운영체제 또는 애플리케이션이 담겨 있는 **'이미지(Image)'**가 필요합니다.

*   **이미지의 개념:** 이미지는 컨테이너를 만들 때 사용되는 설계도 역할을 하며, 그 위에 여러 겹의 레이어(Layer) 구조로 구성됩니다.
    *   *(참고)* 이미지는 베이스 OS(기본 운영체제 파일 시스템), 추가 패키지 레이어, 그리고 실행 중 변경되는 내용(컨테이너 레이어)으로 이루어져 있습니다.
*   **이미지 다운로드 (`docker pull`):** 도커 허브 등 외부 레지스트리에서 필요한 이미지를 로컬 환경으로 가져오는 명령어입니다.
    *   명령 형식: `docker pull [이미지 이름]:[태그]`
    *   이때 태그를 붙여 특정 버전이나 날짜의 버전을 명확하게 지정할 수 있습니다.

## 2. 컨테이너 기본 생성 및 라이프사이클 관리
다운로드 받은 이미지를 실제로 구동하여 독립된 환경을 만드는 과정입니다.

### A. 컨테이너 생성 및 실행 (`docker run`)
*   **핵심 명령어:** `docker run`은 이미지를 기반으로 새로운 **컨테이너(Container)**를 생성하고 동시에 실행까지 시켜주는 명령입니다.
*   **주요 옵션:**
    *   `-it`: 인터랙티브(Interactive) 모드를 활성화하여, 컨테이너가 열렸을 때 사용자가 직접 명령어를 입력할 수 있는 쉘 환경을 할당합니다. (Shell access를 위해 필수적)
    *   `--name [이름]`: 생성되는 컨테이너에 사람이 기억하기 쉬운 이름을 부여합니다.
    *   *(구조)* `docker run -it --name [이름] [이미지 이름]`

### B. 컨테이너 상태 관리 명령어 (Lifecycle Commands)
컨테이너는 생명주기를 가지므로, 다양한 명령어로 상태를 제어할 수 있습니다.

*   **확인:**
    *   `docker ps`: 현재 **실행 중(Running)**인 컨테이너 목록을 보여줍니다.
    *   `docker ps -a`: 실행된 기록이 있는 모든 컨테이너(종료, 정지 포함)를 보여줍니다.
*   **제어:**
    *   `docker stop [이름/ID]`: 컨테이너를 정상적으로 **정지(Stop)**시킵니다. (동작 중인 컨테이너만 종료 가능)
    *   `docker start [이름/ID]`: 정지된 컨테이너를 다시 **실행(Start)**시킵니다.
    *   `docker rm [이름/ID]`: 완전히 삭제하는 명령어입니다. (*Tip: 반드시 `stop`된 상태여야 삭제 가능*)
*   **재접속 (Execution):**
    *   `docker exec -it [컨테이너 이름]:[명령어]`: 이미 생성되어 **작동 중인 컨테이너 내부로 다시 접속**하여 명령을 수행합니다. (`run`은 새로 만드는 것이고, `exec`는 내부 진입입니다.)

## 3. 데이터 영속성 확보: 볼륨과 마운트 개념
컨테이너의 가장 큰 특징이자 주의할 점은 **'휘발성(Ephemeral)'**이라는 것입니다.

*   **문제점:** 기본적으로 컨테이너 내부에서 생성하거나 변경한 모든 데이터는 컨테이너가 삭제되면 *함께 사라집니다.* (컨테이너 레이어에 저장된 내용)
*   **해결책: 볼륨 또는 바인드 마운트(Volume/Bind Mount):** 이 개념은 데이터를 컨테이너 외부, 즉 호스트 컴퓨터의 로컬 디렉터리에 별도로 저장하는 방식입니다.
    *   이 설정을 통해 컨테이너가 삭제되어도 내부에서 사용하던 중요한 데이터는 안전하게 보존할 수 있습니다.

## 4. 다중 서비스 환경 구성: Docker Compose 활용
여러 개의 컨테이너(예: 웹 서버 + DB 서버)를 하나의 애플리케이션처럼 함께 구동해야 할 때, `docker run` 명령어를 매번 복사-붙여넣기 하는 것은 매우 불편합니다.

*   **도커 컴포즈의 역할:** `Docker Compose`는 여러 개의 컨테이너 서비스와 그들 간의 네트워크, 데이터 설정 등을 하나의 YAML 파일(`.yml`)에 정의하여, 이를 한 번의 명령으로 일괄적으로 관리하고 실행하게 도와주는 도구입니다.
*   **작동 방식 (YAML 정의):**
    1.  서비스 이름과 필요한 이미지를 `docker-compose.yml` 파일에 명시합니다.
    2.  각 서비스가 사용할 포트 설정, 볼륨 마운트 등 복잡한 설정을 이 한 파일을 통해 체계적으로 관리할 수 있습니다.
*   **주요 명령어:** (YAML 파일이 있는 디렉토리에서 실행해야 합니다.)
    *   `docker-compose up`: 정의된 모든 서비스를 생성하고 네트워크에 연결하여 **상황을 띄웁니다.**
        *   `up -d`: 백그라운드 모드(Detached Mode)로 서버를 동작시킵니다. (가장 많이 사용)
    *   `docker-compose down`: Compose 파일로 구동된 모든 서비스를 안전하게 중지하고 제거합니다.
    *   **컨테이너 내부 진입:** `docker-compose exec [서비스 이름] [명령어]`를 사용하여 특정 서비스 컨테이너의 내부로 접속할 수 있습니다.

## 1. 리눅스 학습 환경 구축의 필요성: 도커(Docker) 소개
- **학습 목표:** 본 강의는 운영체제(OS)인 리눅스를 실제로 사용해 보는 것을 목표로 합니다.
- **환경 구축의 어려움 및 해결책:**
    - 직접 리눅스가 설치된 컴퓨터를 구매하기 어렵기 때문에, 개발자들은 '가상 환경'을 통해 학습합니다.
    - 이 가상 환경을 구현하는 도구가 바로 **도커(Docker)**입니다. 도커는 내 컴퓨터 안에 또 다른 운영체제를 가진 '컴퓨터 안의 컴퓨터'(컨테이너)를 만들어낼 수 있게 합니다.
- **기본 과정:** 리눅스 이미지를 다운로드(`pull` 명령어 사용)하여, 이 이미지를 바탕으로 컨테이너(격리된 가상 환경)를 생성하고 관리합니다.

## 2. Docker Compose를 이용한 컨테이너 관리 및 운영
- **도커 컨테이너의 역할:** 단일 서비스나 여러 개의 서비스를 하나의 패키지로 묶어 관리할 수 있습니다. 특히 '여러 개의 컨테이너'를 한 번에 설정하고 운영하는 데 매우 유용합니다.
- **`docker-compose` 사용 원리:**
    - YAML 파일(`docker-compose.yml`)이라는 정해진 형식의 파일을 사용하여 여러 서비스(컨테이너) 설정을 정의합니다. (설정서 역할)
    - 이 방법을 사용하면 복잡한 컨테이너 환경을 빠르고 일관성 있게 구축할 수 있습니다.
- **주요 명령어와 기능:**
    - `docker-compose up`: YAML 파일에 정의된 모든 서비스를 백그라운드로 실행하고 필요한 컨테이너를 생성합니다.
    - `docker-compose down`: Compose 파일에 포함된 모든 서비스와 네트워크 리소스를 한 번에 정리(삭제)하여 깨끗하게 환경을 초기화할 수 있습니다.
    - **활용성:** 서버 배포 시 복잡한 데이터베이스(예: MySQL) 등 여러 컴포넌트를 한꺼번에 띄우고 관리하는 데 핵심적으로 사용됩니다.

## 3. 외부 접속을 위한 SSH(Secure Shell) 설정 심화
- **SSH의 필요성 (원격 접속):**
    - 우리가 공부하는 리눅스 서버가 내 로컬 컴퓨터에 설치된 것이 아니라, AWS와 같은 '외부 클라우드'나 회사 데이터센터 등 원격지에 존재할 수 있습니다.
    - 이때 외부 장소에서 내부 서버로 안전하게 접근하기 위한 통로 역할을 하는 것이 **SSH(Secure Shell)**입니다.
- **도커 환경에서의 SSH 구현:**
    - 도커 컨테이너 내부에 마치 실제 서버처럼 작동할 수 있도록 OpenSSH 서버를 설치해야 합니다.
    - 이를 위해 `Dockerfile`을 작성하여 컨테이너가 실행되는 과정에 다음 동작들을 포함시킵니다:
        1. 운영체제 업데이트 및 필수 패키지(`openssh-server`, `sudo` 등) 설치.
        2. SSH 서비스가 열릴 수 있도록 설정 및 디렉터리 생성.
        3. 루트(root) 비밀번호와 키젠 설정을 포함합니다.
- **컨테이너 연결 포트 설정:**
    - 서버에 외부에서 접속하려면 방화벽(포트)을 반드시 열어줘야 합니다.
    - `docker-compose.yml`의 Port Mapping 기능을 사용하여, 컨테이너 내부의 SSH 기본 포트(22번)를 로컬 컴퓨터의 다른 사용 가능한 포트(예: 2222번)와 연결해줍니다. (로컬 22번과 충돌 방지 목적).

## 4. 전체 과정 복습 및 핵심 정리: 가상 환경 접근 방법 총정리
- **핵심 목표:** 리눅스 명령어를 연습하기 위해, 통제된 격리 공간(컨테이너) 내부에 접속하는 방법을 익히는 것입니다.
- **다양한 컨테이너 접근 방법 비교:**

| 방법 | 설명 | 주로 사용되는 상황 | 목적 |
| :--- | :--- | :--- | :--- |
| `docker run` | 명령어 옵션들을 주어 단일 컨테이너를 생성 및 실행합니다. | 간단하고 임시적인 테스트 환경 구축 시 | 격리된 리눅스 환경 만들기 |
| `docker-compose up` | 정의된 YAML 파일에 따라 복잡한 여러 서비스(DB, Web 등)가 포함된 환경을 일괄 구축합니다. | 실제 시스템 아키텍처를 모방하여 배포하는 경우 | 대규모/다중 컨테이너 관리 |
| `docker exec -it` | 이미 실행 중인 컨테이너 내부로 직접 터미널 세션을 열고 진입할 때 사용합니다. | 컨테이너가 살아있는 상태에서 명령어 실행 및 확인이 필요할 때 | 서비스 유지 중 문제 해결, 내부 작업 수행 |
| SSH 접속 (포트 포워딩) | 외부 IP 주소와 공인된 포트를 통해 원격지 서버에 안전하게 접근하는 방법입니다. | AWS, 데이터센터 등 물리적으로 분리되어 있는 곳의 서버를 사용할 때 | 네트워크 보안을 유지하며 원격 제어 권한 획득 |

- **결론 및 시사점:**
    - **개발자 관점:** 컨테이너 기술(Docker)은 환경 의존성을 제거하고, 누구나 동일하게 작동하는 '재현 가능한' 개발/운영 환경을 구축할 수 있게 해주므로 매우 유용합니다.
    - **배우는 것의 의미:** 실제 서버는 외부 네트워크에 연결되는 경우가 많으므로, 단순히 컨테이너를 띄우는 능력뿐 아니라, SSH 같은 원격 접근 기술까지 이해하고 있어야 실무에서 활용할 수 있습니다.

## 1. 컨테이너 환경과 배포 전략 이해 (Docker & Docker Compose)
*   **가상환경의 진화:** 과거에는 VM(Virtual Machine)을 사용하여 운영체제를 격리하거나 필요한 환경(예: Mac에서 Windows 구동)을 구축했습니다. 하지만 이는 무겁고 복잡하다는 단점이 있었습니다.
*   **도커(Docker)의 역할:** 도커는 가상환경보다 더 컴팩트하고 효과적으로 서비스를 실행할 수 있도록 '컨테이너' 개념을 제공하며, 환경 관리를 용이하게 합니다.
*   **주요 사용 명령어 및 기능:**
    *   `docker run`: 원하는 이미지를 기반으로 컨테이너를 생성하고 실행합니다.
    *   `docker-compose up`: 여러 서비스와 관련된 여러 개의 컨테이너들을 한 번에 설정(설정 파일: `docker-compose.yml`)하고 묶어서 관리할 때 사용합니다.
    *   **원격 접근:** SSH(Secure Shell)를 이용하여 외부에 있는 원격 컴퓨터 또는 내부 컨테이너에 안전하게 접속할 수 있습니다. (컨테이너 실행 중에도 `exec` 명령을 사용하여 내부로 진입 가능)

## 2. 리눅스 시스템 관리 및 패키지 관리 방법
*   **시스템 관점의 목표:** 서버를 운영하거나 애플리케이션을 배포하기 위해 필요한 기본적인 시스템 명령어들을 학습합니다 (패키지 관리, 파일 조작, 모니터링, 네트워크 설정 등).
*   **패키지 매니저의 중요성:** 리눅스 시스템에서 소프트웨어와 응용 프로그램(앱) 관리를 담당하는 핵심 도구입니다.
    *   필요한 패키지를 다운로드받아 설치하고, 의존성을 관리하며, 제거할 수 있게 해줍니다 (예: `npm`이 Node.js의 패키지 매니저인 것과 원리적 유사).
    *   주요 매니저는 `yum`이나 `dnf` 등이 있으며, 이들은 시스템에 최소한의 기능만 포함된 경량화된 OS 이미지를 효율적으로 관리할 수 있게 합니다.
*   **핵심 명령어 활용 (예시):**
    *   **설치:** 필요한 패키지 설치 시 (`yum install [패키지명]`). `-y` 옵션은 모든 질문에 'Yes'로 자동 응답하게 하여 스크립트 등에 유용합니다.
    *   **삭제:** 사용하지 않는 패키지를 제거할 때 (`yum remove [패키지명]`).
    *   **위치/정보 확인:** 특정 명령어의 위치를 찾거나(`which`), 상세 정보를 확인할 때(`info`) 유용하게 사용할 수 있습니다.

## 3. 쉘(Shell) 사용법과 기본 디렉토리 구조
*   **쉘(Shell)의 개념:** 운영체제와 상호작용하는 사용자 인터페이스입니다 (예: Bash Shell). 시스템 환경을 확인하거나 명령어를 실행할 때 사용합니다.
*   **환경 변수 (Environment Variables):** 현재 쉘 세션에서 정의되어 있는 값들로, 프로그램이나 시스템이 특정 정보를 인식하는 데 사용됩니다.
    *   `$PATH`: 시스템에서 명령어를 찾을 경로가 설정되어 있습니다.
    *   `$HOME`: 현재 사용자(User)의 기본 홈 디렉토리 경로를 나타냅니다.
*   **파일 구조 및 접근:**
    *   **디렉토리 탐색:** `cd`, `ls`, `pwd` 같은 기본적인 파일 시스템 명령을 사용하여 원하는 위치로 이동하고 내용을 확인합니다.
    *   **루트(Root)와 홈 디렉토리:** 모든 파일 시스템의 최상위 경로는 `/` (루트 디렉토리)입니다. 사용자마다 독립적인 작업 공간인 `$HOME` 디렉토리가 존재하며, 이는 각 사용자가 격리된 권한을 가질 수 있도록 합니다.

## 4. 사용자 및 그룹 계정 관리와 권한 설정
*   **사용자/그룹의 개념:** 리눅스는 '최소 권한 원칙'에 따라 사용자(User)와 그룹(Group)이라는 개념으로 시스템 접근 권한을 나눕니다. 어떤 자원에 접근할 수 있는지, 무엇을 수정할 수 있는지를 이 계정 구조를 통해 통제합니다.
*   **주요 관리 작업:**
    *   **사용자 생성 및 삭제:** `useradd` 명령어를 이용해 새 사용자를 추가하고 (`useradd [유저명]`), `userdel`로 사용자를 제거합니다.
        *   *(Tip)* 유저를 삭제할 때, 해당 유저의 홈 디렉토리까지 완전히 지우려면 옵션(`-r`)을 지정해야 합니다.
    *   **비밀번호 설정:** `passwd [유저명]` 명령어를 통해 접근 비밀번호(Password)를 부여합니다. 보안을 위해 복잡한 패스워드를 설정하는 것이 중요합니다.
    *   **그룹 관리 및 권한 제어:**
        *   사용자는 하나 이상의 그룹에 소속될 수 있으며, 리눅스는 **'그룹' 단위로도 접근 권한**을 부여할 수 있습니다.
        *   이를 통해 특정 파일이나 디렉토리에 대한 접근 통제와 권한 관리를 수행합니다.
    *   **최고 관리자 권한 사용:** 일반 사용자가 시스템 설정을 변경하거나 민감한 작업을 할 때는 `sudo` 명령어를 사용하여 임시적으로 관리자(Root)의 권한을 요청해야 합니다.

## 1. 사용자 및 그룹 관리 원리 이해 (User & Group Management)
*   **핵심 개념:** 리믹스 계열 시스템에서 **사용자(User)**와 **그룹(Group)**의 관계를 이해하는 것이 중요합니다.
    *   시스템은 사용자를 생성할 때 기본적으로 그룹을 함께 생성해 주며, 사용자는 이 그룹에 포함됩니다.
    *   특정 사용자가 특정 그룹에 속하게 됨으로써 해당 그룹이 가진 권한을 상속받아 사용할 수 있습니다.
*   **권한 관리의 구조:** 파일 시스템에서 권한 관리는 다음과 같이 분리되어 처리됩니다.
    *   개인(User)에 대한 권한
    *   그룹(Group)에 대한 권한
    *   전체(Other)에 대한 권한
    *   이러한 방식으로 사용자, 그룹, 전체의 세 가지 관점에서 권한을 관리할 수 있습니다.

## 2. 리눅스 시스템 기본 파일 구조 및 정보 확인
*   **사용자/그룹 식별:** 운영체제는 `/etc` 디렉터리 하위의 파일을 통해 사용자 및 그룹 정보를 관리합니다.
    *   `/etc/passwd`: 사용자의 계정 정보를 담고 있습니다 (비밀번호 등 민감 정보는 노출되지 않음). 사용자 이름, UID(사용자 식별 번호), 홈 디렉토리, 로그인 셸 등의 정보를 확인할 수 있습니다.
    *   `/etc/group`: 그룹 정보를 담고 있습니다. 그룹 ID, 그룹명, 그리고 해당 그룹에 속한 사용자 목록을 알 수 있습니다.
*   **시스템 관리의 원칙 (권장 사항):**
    *   서버를 관리하는 전문 개발자(백엔드 개발자)라 할지라도, 모든 작업을 **루트 계정**으로 진행할 필요가 없습니다.
    *   정보 보안 및 권한 관리를 위해 사용자별로 적절하게 생성된 전용 계정을 부여받아 사용하는 것이 원칙입니다.

## 3. 파일 권한(Permission) 관리 심화 학습
*   **권한의 이해:** 파일 시스템은 각 항목에 대해 소유자, 그룹, 전체 세 영역에 걸쳐 읽기(Read), 쓰기(Write), 실행(Execute) 권한을 부여합니다.
    *   이러한 권한 설정(예: `rwx`)은 개발자가 이해하고 필요할 때 적용할 수 있어야 합니다.
*   **권한 확인 명령어 (`ls -l`):** 파일의 세부 정보를 볼 때, 가장 앞에 나오는 문자는 해당 객체가 디렉터리인지 일반 파일인지 알려주며, 이후 일련의 문자열(rwx)은 권한을 나타냅니다.
    *   예시: `읽기쓰기 실행 (User) | 읽기 실행 (Group) | 읽기 실행 (Other)` 순서로 해석할 수 있습니다.
*   **권한 수정 및 관리:** 명령어들을 통해 파일의 소유자, 그룹, 그리고 세 가지 권한 영역(사용자/그룹/전체)을 설정하고 변경하는 것이 가능합니다.

## 4. 디렉터리 및 파일 명령어 실습 (`mkdir`, `rm`, `cp`, `mv`)
*   **디렉터리 생성 (Directory Creation):**
    *   `mkdir [디렉토리 이름]`: 기본적인 디렉터리를 생성할 때 사용합니다.
    *   `mkdir -p`: 부모 디렉터리가 없더라도 한 번에 여러 개의 중첩된 디렉터리를 순차적으로 생성하는 옵션입니다.
*   **디렉터리/파일 삭제 (Removal):**
    *   `rm [파일명]`: 일반 파일을 삭제합니다.
    *   `rm -r [디렉토리명]`: **가장 중요하게 사용되는 명령으로,** 디렉터리와 그 내부의 내용을 재귀적(Recursively)으로 완전히 삭제할 때 사용합니다. (주의하여 사용해야 합니다.)
*   **파일 복사 및 이동 (Copy & Move):**
    *   `cp [원본 파일] [대상 파일명]`: 파일을 원하는 위치로 사본을 만들어 복사하는 명령어입니다.
    *   `cp -r [디렉토리 원본] [대상 디렉토리]`: 디렉터리 전체를 통째로 복사할 때 `-r` 옵션을 사용합니다.
    *   `mv [원본 파일] [새 위치/파일명]`: 파일을 다른 디렉터리로 이동시키거나, 이름을 변경하는 데 사용하는 명령어입니다. (이동과 이름변경 두 가지 용도가 있습니다.)
*   **추가 학습 권장 사항:**
    *   실제 개발 환경에서는 마우스로 하는 복사/붙여넣기 등의 작업도 모두 위와 같은 **명령어 기반의 효율적인 방식**으로 처리하는 것이 일반적입니다.
    *   이러한 리눅스 명령어들은 습관적으로 사용할 수 있을 만큼 여러 번 반복하여 연습할 필요가 있습니다.

## 1. 운영체제의 기본 개념과 CLI 환경의 필요성
- **운영체제(OS)의 역할:** OS는 하드웨어와 소프트웨어를 연결해주는 접점 역할을 하며, 모든 컴퓨터가 작동하기 위해 필수적이다. (예: Windows, macOS, Linux).
- **GUI vs CLI 비교:**
    *   **그래픽 사용자 인터페이스(GUI):** 마우스 클릭 등 직관적인 방식으로 쉽게 정보를 찾고 사용할 수 있도록 발전한 형태 (Windows의 핵심 인기 요인). 일반 사용자를 위한 환경이다.
    *   **명령줄 인터페이스(CLI) / 커맨드라인:** 명령어를 직접 입력해야 하는 방식. 구동되는 코드가 백엔드나 서버 애플리케이션일 경우, GUI보다 **가볍고 안전하며 컴팩트하게 동작**할 수 있어 주로 사용된다.
- **Linux의 중요성:** 우리가 백엔드 개발을 하거나 실제 서비스를 제공하는 컴퓨터 운영체제는 리눅스 같은 CLI 기반 OS를 주로 사용하기 때문에, 기본적인 명령어 숙지가 필수적이다.

## 2. 파일 권한 시스템 이해 및 관리 (chmod)
- **파일의 속성:** 모든 파일과 디렉토리(폴더)는 '권한'을 가지고 있다. 이 권한이 부족하면 해당 파일을 실행하거나 접근하는 것 자체가 실패할 수 있다.
- **권한 구조 파악 (rwx):** 파일은 다음과 같은 세 가지 주체에 따라 읽기(Read, r), 쓰기(Write, w), 실행(Execute, x) 권한으로 구분된다.
    1.  **소유자 (Owner)**: 파일을 만든 사용자.
    2.  **그룹 (Group)**: 소유자가 속해 있는 그룹의 멤버.
    3.  **기타 사용자 (Other/World)**: 위 두 주체에 속하지 않은 모든 사용자.
- **권한 표기법:**
    *   **문자 방식 (rwx):** `ls -la` 명령 등으로 확인할 수 있으며, 세 부분(소유자/그룹/기타)이씩 묶여 표시된다.
    *   **숫자 방식 (8진수, Octal):** 각 권한에 숫자가 부여되어 관리하기 용이하다. (읽기=4, 쓰기=2, 실행=1).
        *   예시: `755`는 소유자에게(7=rwx), 그룹과 기타 사용자 모두에게(5=rw-) 각각의 모든 권한을 주는 의미이다.
- **권한 변경 명령어 (`chmod`):**
    *   **숫자 이용:** 특정 파일에 원하는 모드를 설정할 때 사용한다. (예: `chmod 755 [파일명]`).
    *   **기호 이용:** 특정 사용자에게 권한을 추가(+), 삭제(-)하는 방식으로 유연하게 관리할 수 있다.
        *   예시 1: 소유자에게 실행 권한 추가 (`u+x`).
        *   예시 2: 그룹 사용자의 쓰기 권한 제거 (`g-w`).

## 3. 파일 유형 및 심볼릭 링크 활용법
- **파일의 종류 구분:** 리눅스 환경에서 모든 요소는 다음과 같이 세 가지로 분류된다.
    1.  **일반 파일 (Regular File):** 내용물이 있는 일반적인 데이터 파일.
    2.  **디렉토리 (Directory):** 다른 파일이나 디렉토리를 담는 폴더 역할. 내부적으로도 하나의 파일처럼 권한 관리가 된다.
    3.  **심볼릭 링크 (Symbolic Link, Soft Link):** 특정 경로를 단축하거나 가리키는 '바로가기 아이콘' 역할을 한다. 실제 데이터가 아닌, *경로* 자체에 대한 포인터이다.
- **링크 생성 (`ln -s`):**
    *   `ln -s [원본_경로] [새로운_링크이름]` 형태로 사용한다.
    *   심볼릭 링크는 원본 파일의 경로만 가지고 있기 때문에, 원본이 삭제되면 링크도 무용지물이 된다 (고아 상태가 될 수 있음).

## 4. 시스템 사용자 관리 및 고급 명령 (sudo, su, chown)
- **`sudo` 명령어:** 슈퍼유저(Root) 권한으로 특정 명령어 하나만 실행할 수 있도록 허용하는 명령어이다. 아무나 임의로 root 권한을 가질 수는 없으며, 루트가 의도적으로 권한을 부여해야 한다.
- **사용자 전환 (`su`):** 현재 로그인된 사용자에서 다른 계정(예: Root)으로 사용자를 변경할 때 사용한다.
    *   실행 시에는 비밀번호 입력이 필요하지만, Root 계정에서 다른 일반 계정으로 이동할 때는 비밀번호 없이 이동할 수 있는 특징도 있다.
- **소유권 변경 (`chown`):** 파일의 소유자나 그룹을 다른 사용자/그룹으로 바꿀 때 사용한다. (예: `chown [새로운_소유자]:[새로운_그룹] [파일명]`).

## 5. 종합 실습 요약 및 다음 학습 방향
- **실행 흐름 복습:** 이 강의 내용을 통해 파일 생성, 권한 부여, 링크 생성, 사용자 전환 등 기본적인 리눅스 명령어 사용법을 익혔으며, 특히 각 명령어가 어떤 동작 원리를 가지는지 이해하는 것이 중요하다.
- **스크립팅 기본:** `echo`와 리다이렉션 기호 (`>`)를 이용해 파일에 내용을 채우고, 실행 권한(x)을 부여하면 실제 스크립트처럼 실행할 수 있다. (첫 줄의 Shebang은 해석기를 지정하는 역할을 한다).
- **다음 학습 목표:** 배운 지식을 활용하여 **Docker와 컨테이너** 개념을 익히는 것이 다음 단계로 중요하다. 가상 환경(컨테이너) 내에서 리눅스 명령들을 실제로 연습하며 숙련도를 높일 것을 권장한다.
