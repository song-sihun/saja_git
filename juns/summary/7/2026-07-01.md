## 1. 오리엔테이션 및 현황 점검
- 강의 시작 전, 수강생들의 근황(기분, 컨디션)을 확인하며 친목을 다지는 시간을 가짐. (지나친 대화 내용은 요약에서 제외하고 흐름만 녹임)
- 피로도가 누적되기 쉬운 시기이므로, 방과 후에는 충분한 휴식 및 컨디션 관리가 중요함을 강조함.

## 2. 리액트의 필요성: Single Page Application과 DOM 이해
**Single Page Application (SPA)**
- 웹 애플리케이션 전체가 단일 페이지에서 동작하는 형태를 의미한다.
- SPA는 매우 효율적이지만, 내용이 바뀔 때마다 브라우저 화면을 새로 그려내는 과정(DOM 조작)은 리소스에 부담을 줄 수 있다.

**Document Object Model (DOM)**
- HTML 태그들을 개체로 추상화하여 관리하는 방식이다. 모든 웹 브라우저는 이 DOM을 통해 화면을 그린다.
- JavaScript를 이용해 HTML 요소를 생성하거나 속성을 변경할 수 있게 도와주는 인터페이스다.

**Virtual DOM (가상 DOM)의 도입 이유와 역할**
- **문제점:** 실제 DOM은 복잡하고 조작에 시간이 많이 소요된다.
- **솔루션:** 가상 DOM은 메모리 상에서 DOM 구조를 똑같이 재현한(직접 그리지는 않는) 모델이다.
- 리액트는 이 가상 DOM을 이용하여 변화가 생겼을 때, 전체를 다시 그리는 대신 *실제 DOM과 비교하여* 달라진 부분만을 찾아내어 업데이트한다. 이를 통해 성능을 획기적으로 개선한다.

## 3. 컴포넌트 기반 아키텍처와 핵심 개념
- **컴포넌트(Component):** 웹 페이지의 작은 '조각' 단위로 화면을 구성하는 독립적인 함수(자바스크립트 함수)이다.
    - 필요한 UI 조각들을 하나의 컴포넌트로 만들어 재사용하고, 이 컴포넌트들을 조합하여 원하는 전체 화면을 완성한다.
- **Props (프롭스):** 부모 컴포넌트가 자식 컴포넌트에 데이터를 전달할 때 사용하는 속성 값이다. (읽기 전용 데이터)
- **State (상태):** 컴포넌트 내부에서 관리되며, 시간이 지남에 따라 변화할 수 있는 데이터이다. 이 '상태'의 변화가 발생하면 해당 컴포넌트는 다시 실행(Re-render)되어 화면이 갱신된다.

## 4. 필수 React Hooks 마스터하기 (`useState`, `useRef`, `useEffect`)
Hooks는 클래스에 의존하지 않고 함수형 컴포넌트에서 리액트의 기능(상태 관리, 라이프사이클 등)을 사용할 수 있도록 도와주는 핵심 도구이다.

### 📚 useState (상태 저장 및 관리)
- **목적:** 컴포넌트가 변화시킬 수 있는 상태(State)를 선언하고 관리한다.
- **작동 원리:** `useState`를 사용하여 값을 변경하면, 리액트는 이를 감지하고 해당 컴포넌트를 자동으로 재실행(Re-render)하여 화면에 새로운 값으로 반영한다.

### 📚 useRef (참조 및 메모리 사용)
- **목적 1: DOM 직접 접근:** 특정 HTML 요소를 JavaScript 코드에서 참조하거나 조작할 때 사용한다. (DOM 요소 그 자체를 가리킴)
- **목적 2: 값을 유지하되, 재렌더링을 유발하지 않을 때:** 컴포넌트가 매번 리렌더링 되어도 초기화되지 않고 값이 계속 보존되어야 하는 값(예: 타이머 ID 등)에 사용한다.

### 📚 useEffect (부수 효과 처리 - Side Effect)
- **목적:** 컴포넌트의 생애 주기(Life Cycle) 중 특정한 시점(마운팅, 업데이트, 언마운트)에 부가적인 작업을 수행할 때 사용한다.
    - *예시:* 데이터베이스에서 데이터를 불러오기 (API 호출), 타이머 설정하기 등 리액트 자체의 렌더링 과정 외부에 영향을 주는 모든 작업.
- **작동 메커니즘:** 이 함수는 필수적으로 두 개의 인자(Argument)를 받는다.
    1. 첫 번째 인자: 실제 실행할 콜백 함수 (Side Effect)
    2. 두 번째 인자 (의존성 배열): 이 값이 변경될 때만 해당 코드를 다시 실행하라는 규칙을 지정한다.

| 사용 시점 | 의존성 배열 설정 | 설명 및 역할 |
| :--- | :--- | :--- |
| **Mounting** (처음 화면에 나타날 때) | `[]` (빈 배열) | 컴포넌트가 딱 한 번만 실행되어 초기화 로직을 수행할 때 사용한다. |
| **Updating** (상태 또는 Props 변화 시) | `[stateVar, prop]` | 지정된 의존성(`stateVar`나 `prop`)의 값이 변경될 때만 내부 함수를 다시 실행한다. |
| **Unmounting** (화면에서 사라질 때) | 반환하는 클린업 함수 (`return () => {...}`) | 컴포넌트가 사라지기 직전에 실행되어, 설정했던 타이머를 멈추거나 구독을 해제하는 등 정리(Cleanup) 작업을 수행한다. |

## 1. React 기초 복습 및 컴포넌트 구조 이해
React를 이용해 간단한 'Todo' 애플리케이션을 구현하며 기본 원리를 복습하는 단계입니다.

*   **컴포넌트 기반 개발:** 화면 전체가 하나의 큰 코드가 아니라, 작고 독립적인 여러 개의 컴포넌트로 나누어 기능과 UI를 구성하고 관리할 수 있음을 확인합니다.
    *   Todo 앱의 경우: 추가, 삭제, 값 수정 등 기본적인 상태 변경(State) 로직이 컴포넌트 내에서 동작함을 실습했습니다.
*   **CSS 적용 방법:** 스타일링은 여러 방식이 있습니다.
    *   외부 CSS 파일 사용 (권장되는 구조): `index.css`와 같이 전체 공용 스타일이나, 컴포넌트별로 전용 CSS 파일을 분리하여 관리할 수 있습니다.
    *   인라인(Inline) 방식: 간단한 예제에서는 속성을 직접 추가하는 인라인 방식으로도 적용이 가능합니다.

## 2. AI를 활용한 개발 환경 구축 (Claude Code 활용)
개발 과정에 Claude와 같은 AI 도구를 통합하는 방법을 학습하고 실제 사용법을 익힙니다.

*   **AI 코드 에디터 도입:** 코딩 작업 환경(IDE) 내에서 직접 AI의 도움을 받아 코드를 작성하고 구조를 생성할 수 있습니다. (Claude Code 활용)
*   **개발 환경 최적화:**
    *   클로드 코드 하단의 상태줄 등을 통해 현재 파일 정보, 에러 메시지 등 다양한 개발 정보를 습득하거나 필요한 디버깅 정보를 요청할 수 있습니다.
    *   다양한 모드(Edit, Flat, Auto 등)를 전환하며 AI의 판단을 보조적으로 활용할 수 있습니다.
*   **주의 사항:** 코딩 지원 기능은 일반적으로 유료 버전(Pro 버전 등)을 사용해야 전체 기능을 이용할 수 있습니다.

## 3. AI 프롬프트 작성 전략: 요구사항 구체화
AI에게 원하는 결과를 얻기 위해서는 단순히 "이런 앱을 만들어줘"라고 요청하는 것보다 훨씬 더 정교하고 구조적인 프롬프트가 필요합니다.

*   **명확한 기능 요구사항 정의:** 애플리케이션에 포함되어야 할 모든 기능을 목록으로 뽑아내는 것이 중요합니다.
    *   예시: (Todo 앱의 경우) 1) 새 할 일 추가, 2) 할일 목록 표시, 3) 항목 삭제 기능, 4) 할 일 개수 표시 등 구체적으로 정의해야 합니다.
*   **컴포넌트 구조 설계:** 단순히 기능을 나열하는 것에 그치지 않고, "이 컴포넌트는 이런 일을 하고, 저 컴포넌트는 저런 역할을 담당했으면 좋겠다"처럼 전체적인 **아키텍처(Architecture)** 레벨의 목적을 제시해야 합니다.
*   **프롬프트 구조화 예시:** 막연한 요청보다 *[기술 스택]로 [애플리케이션 목표]를 만들 건데, [기능 1], [기능 2]가 필요하며, 컴포넌트는 [A], [B]로 분리하고 싶다.* 와 같이 구조화하여 명령을 내리는 것이 가장 효과적입니다.

## 4. AI와 함께 프로젝트 생성 및 코드 검토 실습
이론 학습에서 실제 AI를 활용하여 전체 애플리케이션 구조물을 만들어보고, 그 결과물을 점검하는 워크플로우를 경험합니다.

*   **프로젝트 생성:** Claude Code를 이용해 필요한 디렉토리/폴더에 React 기반의 프로젝트(예: Todo Application) 생성을 요청할 수 있습니다.
    *   이때 필요한 정보 (어떤 언어 사용, 어떤 라이브러리 사용 등)를 명확하게 제공해야 합니다.
*   **생성된 코드 검토 및 개선:** AI가 완성해 준 코드가 곧 완벽한 코드는 아닙니다.
    *   `npm run [start]` 등으로 프로젝트를 실행하여 동작을 확인합니다.
    *   코드 구조, 컴포넌트 이름 명명 규칙(Naming Convention), 상태 관리 로직의 흐름 등을 면밀히 검토하며 **개선할 부분(Refactoring)**을 찾고 직접 수정해나가는 과정이 필요합니다.
*   **심화 학습 팁 (모델 선택):** 만약 AI가 특정 문제에 대해 계속 오류를 발생시킨다면, 현재 사용 중인 모델보다 더 비싸거나 성능이 좋은 상위 모델로 교체하여 재시도하는 것도 효과적인 해결 방법입니다.

## 1. AI 시대, 개발자가 갖춰야 할 핵심 역량
- **AI 활용과 기본기:** AI 도구가 코드 작성에 도움을 줄 수 있지만, 근본적인 개념 지식 없이는 복잡한 로직 수정이나 원하는 대로 요구사항을 반영하기 어렵습니다.
- **지속적인 연습의 중요성:** 코딩 능력은 결국 '연습'으로만 습득할 수 있으며, 웬만한 기능들은 기본기를 다질 경우 스스로 구현해낼 수 있는 것이 가장 좋습니다.
- **개발 배경 지식의 축적:** 기본적인 프론트엔드(Front-end)와 백엔드(Back-end) 개념을 깊이 이해하고 쌓는 것이 AI를 효과적으로 활용하는 토대가 됩니다.

## 2. 비동기 통신과 JavaScript의 발전사
- **비동기 통신의 정의:** 페이지 요청 방식이 아닌, 뒷단 서버에 접속하여 특정 데이터를 가져오거나 전송하는 작업(데이터 중심)을 처리하는 기술입니다.
- **기술적 진화 과정 (정보 습득 순서):**
    1. **AJAX (Asynchronous JavaScript and XML):** 초창기 비동기 통신 기술의 시초로, 브라우저가 네트워크 작업을 수행하고 콜백 큐에서 결과를 기다리는 방식으로 작동했습니다.
    2. **Promise:** 콜백 지옥(Callback Hell) 문제를 해결하기 위해 등장한 개념입니다. 여러 개의 중첩된 함수 호출을 보다 체계적으로 관리할 수 있게 했습니다.
    3. **Async/Await:** Promise를 기반으로 발전하여, 비동기 코드를 마치 동기 코드처럼 읽기 쉽게 작성할 수 있도록 도와준 문법 구조입니다. (가장 권장되는 방식)
- **핵심 개념 이해:** 비동기 통신이 발생하는 과정(예: 서버 응답 대기 시간)을 이해하고, 이에 맞는 상태 처리 로직(로딩/에러)를 구현하는 것이 중요합니다.

## 3. 프론트엔드와 백엔드를 연결하는 데이터 흐름 (CRUD 구현)
- **연동 목표:** 기존 React 컴포넌트는 메모리상의 임시 데이터를 사용했기 때문에, 실제 영속적인 데이터를 다루기 위해 서버(백엔드) API와의 연동이 필수입니다.
- **구현 방식:**
    *   React 앱에서 `fetch` 또는 Axios와 같은 라이브러리를 사용하여 백엔드 서버(예: Spring Boot 기반의 API)에 HTTP 요청을 보냅니다.
    *   **HTTP 메서드 활용 (RESTful API):** 각 CRUD 작업은 특정 HTTP 메서드를 사용합니다.
        -   **GET:** 데이터를 불러올 때 (`@RestController`의 GET 엔드포인트 호출).
        -   **POST/PATCH:** 새로운 데이터 추가 및 수정 시 (데이터를 생성하거나 업데이트할 때 사용).
        -   **DELETE:** 데이터를 삭제할 때.
    *   **비동기 처리 구현:** 서버 통신은 시간이 걸리는 비동기 작업이므로, 반드시 `async`/`await` 문법을 사용하여 API 호출 결과를 기다렸다가(Awaiting) 받아와야 합니다.

## 4. 실전 React 패턴: 상태 관리 및 오류 처리 기법
- **데이터 페칭 (Data Fetching):**
    *   데이터를 가져오는 로직은 컴포넌트가 마운트될 때 한 번만 실행되어야 하므로, `useEffect` Hook을 사용합니다.
    *   의존성 배열(Dependency Array)에 빈 배열(`[]`)을 넣어 초기 렌더링 시점에만 API 호출이 이루어지도록 제어할 수 있습니다.
- **데이터 흐름 관리 (상태 분리):** 데이터의 상태 관리는 세 가지 축으로 나누어 처리하는 것이 바람직합니다.
    *   `data`: 실제로 로딩된 데이터를 저장하는 스테이트.
    *   `isLoading`: 현재 API 호출이 진행 중인지 여부를 나타내는 플래그(Boolean).
    *   `error`: API 통신 중 오류가 발생했는지 정보를 담는 스테이트.
- **최적화 및 고려사항:**
    *   **조건부 렌더링 (Conditional Rendering):** `isLoading`, `error`, `data` 상태를 조합하여 사용자가 현재 어떤 상황(로딩 중, 에러 발생, 데이터 표시)에 있는지를 시각적으로 피드백해 주는 것이 필수적입니다.
    *   **코드 재사용성:** API 호출의 URL이나 기본 요청 구조 등은 하드코딩하지 않고 상수(Constant) 등으로 정의하여 관리하는 것이 좋습니다.

## 1. 학습 참여 및 피드백의 중요성
*   **적극적인 소통 권장:** 단순히 동그라미나 이모티콘으로 대체하기보다, '못 했다', '진도가 느리다' 등의 구체적인 질문이나 피드백을 중간중간 해주어야 강사가 현재 학생들의 이해도를 파악하고 놓치는 부분이 없는지 확인할 수 있다.
*   **개인별 진도 점검:** 전공자부터 처음 시작한 학습자까지 각자의 속도가 다르므로, 개인이 어려움을 느끼는 부분(ex: AI 활용, 서버 설치 설정 등)은 주저하지 말고 질문하여 도움을 받아야 한다.

## 2. 백엔드 서버와 로컬 데이터베이스 연동 이해
*   **백엔드 구축 목적:** 앞서 프론트엔드에서만 동작하던 기능(To-do 목록 추가/삭제 등)이 백엔드를 거치면서 서버에 영구적으로 데이터가 저장되고, 새로고침 후에도 유지되는 방식으로 개선되었다.
*   **로컬 DB 사용의 중요성:** 실제 서비스는 네트워크 연결된 공용 DB를 사용하지만, 현재 실습 단계에서는 각자 PC 환경에서 동작하는 로컬 데이터베이스를 통해 데이터 연동을 구현해야 한다.
*   **설정 값의 우선순위 (Spring Boot 특징):**
    *   프로젝트 기본 설정값(`application.yml` 등)으로 동작하는 것이 원칙이다.
    *   하지만 애플리케이션 실행 시 명령어 인자(Command Line Arguments)로 값을 전달하면, 이 값이 **가장 높은 우선순위**를 가지고 설정을 덮어쓰게 된다.
    *   따라서 DB ID, 사용자명, 비밀번호 등의 설정은 기본 파일 외에 실행 옵션을 통해 직접 지정하여 유연하게 테스트할 수 있다.

## 3. 프론트엔드-백엔드 연동 및 CRUD 구현 원리 (REST API 활용)
*   **API 엔드포인트의 역할:** 백엔드는 클라이언트(프론트엔드)가 요청하는 데이터 처리 기능을 수행하는 '접점' 역할을 하며, 이 접점을 RESTful API로 구성한다.
*   **HTTP 메소드와 기능 매칭 (CRUD):** 데이터를 주고받을 때는 각기 다른 HTTP 메서드를 사용해야 한다.
    *   `GET`: 특정 리소스를 가져올 때 (조회)
    *   `POST`: 새로운 데이터를 생성할 때 (추가)
    *   `PUT`/`PATCH`: 기존 데이터를 수정할 때 (`PATCH`는 일부 속성만 수정하는 데 유용함)
    *   `DELETE`: 데이터를 삭제할 때
*   **전달 방식:** API 호출 시에는 요청 주소(Endpoint URL), 사용할 HTTP 메서드, 그리고 전송할 데이터(Body)를 정확히 지정해야 한다.

## 4. 비동기 처리(Async/Await) 기법과 프로젝트 목표 완성
*   **비동기 처리가 필요한 이유:** 외부 서버와의 API 통신은 시간이 걸리는 작업이며 (비동기적), 이 과정에서 메인 코드가 멈추지 않고 다른 작업을 계속 할 수 있도록 처리해야 한다.
*   **`async/await`의 역할:** 비동기 방식으로 동작하는 함수(API 호출 등)가 완료될 때까지 기다리게 해주는 문법이다.
    *   함수 선언부에 `async`를 붙여야 하고, 반드시 대기해야 할 지점에 `await`을 사용한다. (이것은 '기다린다'는 개념보다는 코드가 해당 작업이 돌아올 때까지 처리 흐름을 잠시 묶어주는 역할을 한다.)
*   **React Hook 활용 (`useEffect`):** 컴포넌트가 마운트될 때 초기 데이터를 가져오는 등의 부수 효과(Side Effect)를 관리하는 데 `useEffect`를 사용한다. 빈 배열 `[]`을 의존성 배열로 넣어주면, 해당 코드는 **컴포넌트가 처음 화면에 나타날 때 단 한 번만** 실행된다.
*   **최종 목표 설정:**
    *   단순히 전역 상태(`useState`)만 변경하던 로직을 모두 수정하여 **비동기 API 호출**을 통해 백엔드 서버와 연동해야 한다.
    *   데이터가 서버에 저장되므로, 페이지를 새로고침하거나 재접속해도 추가/수정된 내용이 남아 있도록 완성하는 것이 목표이다.
*   **학습 방법:** 코드를 따라 치는 것에서 벗어나, **"무슨 기능을 구현해야 하는지?"**부터 스스로 고민하고 해결책을 찾아가며 코딩하는 독립적인 학습 과정을 거치는 것이 가장 중요하다. 막히는 부분이 있을 경우, 주저하지 말고 온라인 채널 등을 통해 질문하여 도움을 받는 것을 권장한다.

## 2. 클라이언트-서버 통신 과정 분석 (Network Tab 활용)

## 3. 비동기 데이터 처리 기술 및 원리 학습
- **AJAX 기술 소개:** 서버에서 데이터를 가져오거나 주고받는 데 사용되는 세 가지 주요 기술이 있으며, 각각의 특징과 활용 방안을 이해해야 합니다.
    *   **Fetch:** 가장 오래된 방식으로 만들어진 비교적 기본적인 API.
    *   **Axios:** 최신 기술로 분류되며, 사용할 경우 모듈 추가가 필요합니다.
    *   **Patch:** React 라이브러리에 기본적으로 포함되어 있는 API입니다.
- **데이터 직렬화 및 역직렬화 과정 (JSON):**
    1.  **서버 응답 수신:** 백엔드 서버로부터 데이터는 JSON 형태의 *문자열(String)*로 전송됩니다.
    2.  **클라이언트 파싱 (역직렬화):** 이 문자열을 JavaScript 객체 형태로 사용하기 위해 `JSON.parse()` 메서드를 사용하여 변환해야 합니다.
    3.  **데이터 상태 업데이트:** 파싱된 데이터를 React의 State(e.g., `setTodos`)에 넣어주면, 상태 변화를 감지하여 컴포넌트가 재렌더링(Re-rendering) 되면서 화면에 변경 사항이 반영됩니다.

## 4. CRUD (생성, 읽기, 수정, 삭제) 기능 구현 흐름 마스터
모든 데이터 조작은 **① 이벤트 발생 → ② 상태 핸들러 호출 → ③ 비동기 API 호출 및 서버 통신 → ④ 백엔드 응답 수신(데이터 업데이트) → ⑤ Local State 업데이트 및 재렌더링**의 순서를 따릅니다.

### 💡 A. 데이터를 불러오는 과정 (Read: 읽기)
- 컴포넌트가 처음 마운트될 때 (`useEffect` 사용), `fetchTodos` 같은 메서드를 호출하여 서버에서 초기 데이터 리스트를 받아옵니다. 이 과정은 상태 값을 초기화하고 DB의 현재 상태로 화면을 표시하게 합니다.

### 💡 B. 할 일 추가하기 (Create: 생성)
- **흐름:** 입력 필드에서 값 변경 → '추가' 버튼 클릭 → 부모 컴포넌트의 핸들러(`onAdd`) 호출 → 내부적으로 API 전송이 트리거됩니다.
- **핵심 기술:** 서버로 데이터를 보낼 때(POST 방식), JavaScript 객체는 반드시 `JSON.stringify()`를 사용하여 JSON 스타일의 문자열 형태로 변환되어야 합니다.
- **결과 처리:** API 호출 성공 시, 백엔드에서 생성된 ID와 함께 업데이트된 할 일 데이터가 리턴되며, 이 값을 전역 상태에 추가하여 리스트를 갱신하고 화면을 재렌더링합니다.

### 💡 C. 완료 여부 변경 (Update: 수정)
- **흐름:** 체크박스 클릭 (`onChange` 이벤트 발생) → 부모 컴포넌트의 핸들러(`onToggle`) 호출 → 내부적으로 API 전송이 트리거됩니다.
- **핵심 기술:** 상태가 일부만 바뀌는 경우(예: 완료 여부 `complete` 필드), 전체 데이터를 보내지 않고 해당 ID와 변경된 값만 포함하여 PATCH 방식으로 요청하는 것이 효율적입니다.
- **결과 처리:** 서버가 업데이트된 할 일 객체를 반환하면, 로컬 상태에서 기존 항목을 새 데이터로 교체(Replace)하고 리스트를 재렌더링합니다.

### 💡 D. 항목 삭제하기 (Delete: 삭제)
- **흐름:** '삭제' 버튼 클릭 (`onDelete` 이벤트 발생) → 부모 컴포넌트의 핸들러(`onDelete`) 호출 → 해당 ID만 포함하여 DELETE 방식으로 API를 호출합니다.
- **결과 처리:** 서버로부터 성공 응답을 받으면, UI에서 제거하기 위해 상태 관리 리스트에서 삭제된 항목의 ID와 일치하는 데이터만 배열에서 `filter` 등의 방법을 이용해 제거(제거 로직)하고 갱신합니다.

## 5. 애플리케이션 아키텍처와 에러 핸들링 주의점
- **컴포넌트와 서버 연결:** 모든 상태 변경 과정은 서버와의 비동기 통신을 거쳐야 합니다. 클라이언트 측의 상태 변화만으로는 데이터가 영구적으로 저장되지 않으며, 반드시 백엔드 API를 호출하여 데이터를 업데이트해야 합니다.
- **CORS (Cross-Origin Resource Sharing) 관리:** 여러 포트에서 동작하는 프론트와 백엔드가 통신할 때 발생하는 CORS 에러는 개발 시 자주 마주치는 문제 중 하나입니다. 서버 설정(백엔드 코드 수정 등)을 통해 어떤 요청과 메서드를 허용할지 명확하게 설정해줘야 합니다.
- **포트 및 보안 이해:** 프론트와 백엔드가 다른 포트로 동작하는 것은 별개의 서버로 인지되기 때문에, 통신이 원활하려면 CORS 등의 설정을 통한 신뢰 관계 확보가 필수적입니다. (요청 시 인증/인가(Security) 설정 필요)

## 1. 라우터(Router)의 개념 이해: 네트워크 장비로서의 라우터
*   **기본 정의:** 라우터는 들어오는 요청(데이터 패킷)의 목적지 주소를 분석하여, 이 데이터를 어느 경로로 보내야 할지 판단하고 안내하는 장치입니다.
*   **작동 원리 (네트워크 비유):** 인터넷에서 구글 페이지에 접속할 때, 공유기나 네트워크 라우터들은 요청이 최종 서버(구글 서버)까지 도달하도록 끊임없이 경로를 찾아 연결해 주는 역할을 합니다.
*   **핵심 기능:** 들어온 요청을 목적지 주소(Destination)를 보고 올바른 방향으로 안내하며, 최적의 이동 경로(Path)를 결정하는 것이 핵심입니다.

## 2. 싱글 페이지 애플리케이션(SPA)과 라우팅의 필요성 및 문제점
### A. SPA 환경에서 라우팅이 필요한 이유 (개념 확장)
*   **현상:** 웹사이트는 홈페이지, 소개 페이지, 게시판 목록 등 여러 개의 '페이지'가 존재해야 합니다. 하지만 React 같은 SPA는 기본적으로 하나의 HTML 파일 내에서 컴포넌트만 교체하며 동작합니다.
*   **문제 발생 지점 (SPA의 한계):** 순수하게 클라이언트 측에서 컴포넌트만 전환할 경우, 다음과 같은 문제가 발생합니다.
    *   **브라우저 히스토리 관리 불가능:** 페이지가 바뀌어도 실제 URL이 변경되지 않습니다. (Ex: 뒤로 가기/앞으로 가기 버튼 작동 불가)
    *   **북마크 불가:** 특정 시점의 상태를 북마크하거나 다른 사람에게 공유할 때 정확한 주소(URL)를 제공할 수 없습니다.
    *   **직접 접근 불가:** 사용자가 브라우저에 URL을 직접 입력하여 원하는 페이지로 접근하는 것이 불가능합니다.

### B. 검색 엔진 최적화(SEO) 문제 (기술적 심화)
*   **정의:** SEO는 웹페이지가 검색 엔진(구글, 네이버 등)에 잘 노출되도록 최적화하는 작업입니다. 검색 엔진은 페이지 내용이 '어디'에서 왔고, 어떤 태그와 가중치를 가지고 있는지를 분석합니다.
*   **SPA의 치명적인 문제:** SPA 방식은 데이터가 주로 클라이언트 측 JavaScript 코드를 통해 동적으로 생성되어 화면에 보여집니다. 이 경우, 검색엔진 크롤러(로봇)는 웹페이지의 **소스 코드(Source Code)**를 읽어 내용을 파악하는데, 중요한 컨텐츠가 JS 실행 후에만 생성되기 때문에 데이터를 추출하기 어렵습니다.
*   **해결책 필요성:** 이러한 문제점들(URL 불일치, 데이터 누락)을 해결하고 안정적으로 검색 엔진에 노출되려면 별도의 라우팅 기술이 필수적입니다.

## 3. React Router DOM을 활용한 라우팅 구현 방법 (기술적 접근)
### A. 역할 및 기능
*   **React Router DOM:** 리액트 애플리케이션에서 표준화된 라우팅을 구현하기 위한 라이브러리입니다.
*   **제공하는 주요 기능:**
    1.  **URL 동기화:** URL 변경에 맞춰 해당 페이지 컴포넌트를 렌더링하고, 컴포넌트의 변화에 따라 URL이 적절히 업데이트되도록 합니다.
    2.  **브라우저 히스토리 관리:** 브라우저의 '뒤로 가기/앞으로 가기' 기능을 정상적으로 지원합니다.
    3.  **컴포넌트 렌더링 제어:** 현재 URL 경로(Path)를 분석하여 어떤 컴포넌트를 보여줄지 결정하고 렌더링합니다.

### B. 구현 단계 요약
1.  **설치:** 프로젝트에 `react-router-dom` 모듈을 설치합니다. (가장 기본이 되는 필수 과정입니다.)
2.  **최상위 감싸기 (`BrowserRouter`):** 애플리케이션의 최상위 레벨 컴포넌트(예: App.js) 전체를 `<BrowserRouter>`로 감싸 라우팅 환경 자체를 활성화합니다. (전역 적용이 목적입니다.)
3.  **라우트 정의 및 설정:**
    *   `<Routes>` 태그 안에 필요한 경로(`path`)와 해당 경로에 매칭될 컴포넌트를 연결하여 정의합니다.
    *   예시: `/todo-list` 주소로 접근하면 `TodoListComponent`가 보이도록 설정합니다.
4.  **링크 걸기:** 일반적인 HTML 방식이 아닌 라우팅 환경에서 링크를 걸 때는 `<Link>` 컴포넌트를 사용하여 내부 페이지 이동(SPA의 네비게이션)을 처리해야 합니다.
