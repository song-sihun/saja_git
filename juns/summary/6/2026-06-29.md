## 1. 과정 개요 및 주말 근황 공유
- 수강생들과 일상적인 안부를 나누며 시작하며, 학습 과정에서 오는 심적 부담감에 대해 공감대를 형성함.
- (간단한 상호작용 시간으로, 핵심 내용은 요약 생략)

## 2. 백엔드와 프론트엔드의 역할 비교
- **백엔드(Backend):** 시스템의 기반이 되는 부분으로, 데이터베이스 처리나 복잡한 로직 처리가 필요하며 상대적으로 많은 배경 지식이 요구됨. (과정 중 가장 부담을 느끼기 쉬운 영역)
- **프론트엔드(Frontend):** 사용자 인터페이스(UI)를 담당하는 부분입니다. 사용자가 보기 좋고 사용하기 편하도록 화면을 구성하는 것이 주요 역할이며, 백엔드에 비해 프로그래밍적 사고가 비교적 덜 부담스러울 수 있음.

## 3. 자바스크립트의 역사적 발전 과정
- **언어의 철학 이해:** 프로그래밍 언어마다 탄생 배경과 목적이 다르므로, 그 특징을 함께 이해하는 것이 학습에 도움이 됩니다. (예: Java는 실력 있는 개발자들이 모여 일관성을 중시하며 만든 언어, Python은 오픈소스 기여가 활발하여 규칙의 유연성이 높은 편)
- **JavaScript의 시작:** 원래 웹 브라우저에서 정적인 HTML 콘텐츠를 동적으로 변경하기 위해 만들어진 스크립트입니다. 처음에는 브라우저 내에서만 작동하는 제한적인 언어였습니다.
- **AJAX 기술의 등장:** 페이지 전체를 새로 요청하여 데이터를 받는 구 방식(전체 리로드) 대신, 필요한 작은 데이터 조각(예: 좋아요 버튼 클릭 시 숫자 1 증가)만을 비동기적으로 주고받는 기술이었습니다. 이를 통해 웹 경험을 혁신적으로 개선했습니다.
- **풀스택 가능성 확장:** 나아가 JavaScript 엔진 기술 발전으로 브라우저 외 영역에서도 동작할 수 있게 되었고, 이는 JavaScript가 프론트엔드뿐 아니라 백엔드까지 담당할 수 있는 '풀스택 언어'로서의 위상을 확립하게 만들었습니다.

## 4. 싱글 페이지 애플리케이션(SPA)과 성능 문제
- **싱글 페이지 애플리케이션 (Single Page Application, SPA):** 초기 웹사이트처럼 페이지마다 이동하는 것이 아니라, 단 하나의 HTML 페이지를 기반으로 내부적으로 내용이 계속 바뀌는 형태의 웹 구조입니다.
    - 모든 인터페이스 요소(회원 목록, 가입 폼 등)가 별도의 페이지로 분리되지 않고 한 곳에서 조작됩니다.
- **과거 SPA 구현의 문제점:** 초기에는 JavaScript가 화면을 동적으로 변경하는 과정 자체가 브라우저의 자원을 과도하게 사용했습니다. 콘텐츠가 조금만 바뀌어도 전체 DOM(문서 객체 모델)을 직접 조작하고 재그리는 과정이 반복되면서 브라우저 성능 저하를 초래했습니다.
- **해결책 제시:** 웹 성능 최적화와 사용자 경험 개선의 필요성이 대두되었고, 이 문제를 해결하기 위한 새로운 기술들이 등장하게 되었습니다.

## 5. React의 핵심 동작 원리 이해 (Virtual DOM, 컴포넌트 기반 구조)
**A. 컴포넌트 기반 아키텍처:**
- 리액트는 **UI를 독립적이고 재사용 가능한 작은 단위(컴포넌트)**로 분리하여 개발하는 방식을 채택합니다.
- 마치 레고 블록처럼 작은 컴포넌트들을 조합하여 복잡한 사용자 인터페이스 전체를 구성합니다.

**B. Virtual DOM (가상 돔):**
- 리액트는 실제 브라우저의 DOM을 직접 조작하는 대신, 자바스크립트 메모리 상에 **Virtual DOM이라는 가상의 객체 모델**을 유지합니다.
- 상태(State)가 변경될 때마다 전체 DOM을 건드리는 것이 아니라, 새로운 Virtual DOM과 이전 Virtual DOM을 비교하는 고도화된 알고리즘을 사용합니다 (Diffing Algorithm).
- 이 과정을 통해 변경된 부분만 정확히 파악하여 최소한의 영역만 실제 브라우저에 그려내기 때문에(렌더링), 성능이 매우 효율적입니다.

**C. 단방향 데이터 흐름 (One-Way Data Flow):**
- 컴포넌트 간 데이터가 항상 **부모(Parent)에서 자식(Child)으로 한 방향**으로만 전달됩니다.
- 이는 데이터의 흐름을 예측 가능하게 만들고, 프로그램 구조를 훨씬 명확하고 추적하기 쉽게 만듭니다.

## 6. 웹 기술 스택 분석 및 전망
- **React의 의의:** 리액트는 SPA 방식으로 페이지 전체가 아닌 '데이터'만 서버로부터 받아와서, 이를 효율적으로 조작하여 화면을 업데이트하는 방식에 최적화된 라이브러리입니다. 이로 인해 웹 애플리케이션 개발 흐름에서 필수적인 기술이 되었습니다.
- **기술 스택 비교:**
    * **React (라이브러리):** UI 렌더링에 집중하는 강력한 라이브러리로, 필요한 기능(라우팅, 상태 관리 등)은 다른 독립적인 라이브러리를 조합하여 사용할 수 있어 자유도가 높습니다. 현재 시장에서 가장 높은 선호도를 보이며 인기를 얻고 있습니다.
    * **Vue / Angular (프레임워크):** 전체 개발 구조와 규칙이 정해져 있는 틀(Framework)을 제공합니다. 프레임워크는 체계적인 개발을 도와주지만, React 같은 라이브러리는 필요한 부분만 가져다 쓸 수 있다는 장점이 있습니다.
- **결론:** 리액트는 컴포넌트 기반의 설계를 통해 재사용성, 높은 생산성, 그리고 Virtual DOM을 활용한 뛰어난 성능 최적화를 구현하며 현재 웹 개발에서 핵심적인 역할을 하고 있습니다.

## 1. Node 버전 관리 및 이해 (NVM)

*   **Node.js의 역할:** JavaScript를 브라우저 외부 환경에서 실행할 수 있게 해주는 도구입니다.
*   **버전 관리의 필요성:** 프로젝트에 따라 필요한 Node.js 버전이 다를 수 있으므로, 하나의 컴퓨터에 여러 개의 버전을 설치하고 전환하며 사용할 수 있는 도구가 필수적입니다.
*   **NVM (Node Version Manager):**
    *   NVM은 'Node 버전 매니저'의 약자로, 다양한 Node.js 버전들을 쉽게 설치하고 관리할 수 있게 돕는 핵심 도구입니다.
    *   이를 통해 프로젝트별로 적합한 Node 버전을 선택하고 활성화(use)하여 사용할 수 있습니다.
*   **LTS (Long Term Support):**
    *   '장기간 지원되는 버전'을 의미합니다. 일반적으로 안정성이 높고 장기간 사용하기에 권장되는 기준 버전이므로, 새로운 프로젝트를 시작할 때는 LTS 버전을 사용하는 것이 좋습니다.

## 2. React 프로젝트 생성 과정 (Vite 활용)

*   **프로젝트 관리 도구의 변화:** 과거에는 `create-react-app` 같은 명령을 많이 사용했지만, 최신 환경에서는 **Vite(비트)**라는 빌드 도구를 이용한 생성이 권장됩니다.
    *   Vite는 기존 생성 방식이 무겁거나 설정이 복잡했던 단점을 개선하여 빠르고 간편하게 프로젝트를 구성할 수 있도록 도와줍니다.
*   **프로젝트 생성 절차:**
    1.  터미널을 열고 `npm create vite` 명령어를 실행합니다.
    2.  생성할 **프레임워크(Framework)**와 사용 언어(**JavaScript/TypeScript**)를 선택합니다. (React, JavaScript 조합이 일반적)
    3.  프로젝트명 지정 후 생성이 완료되면 기본 구조가 구축됩니다.
*   **npm vs. Vite:**
    *   `npm`은 Node Package Manager의 약자로, 노드 프로젝트 관리자 역할을 합니다.
    *   Vite는 단지 `npm`을 실행하는 것을 넘어, 필요한 설정, 라이브러리(dependencies), 빌드 도구 등을 알아서 구성해주는 편리한 도구입니다.

## 3. React 기본 구조와 동작 원리 파악

*   **프로젝트의 핵심 파일:**
    *   **`index.html`:** 웹 애플리케이션의 진입점(Entry Point) 역할을 합니다. 실제 콘텐츠는 이 파일 자체에 존재하는 것이 아니라, JavaScript를 통해 동적으로 주입됩니다.
    *   **`<div id="root">` (또는 유사 ID):** `index.html` 내부에 존재하는 특정한 ID가 지정된 영역이 React 컴포넌트들이 최종적으로 렌더링(표시)되는 공간입니다.
    *   **Javascript 파일 (`main.jsx`/`App.jsx` 등):** 애플리케이션의 동작 로직을 담당하며, 이 코드가 `index.html`의 특정 ID를 찾아가 컴포넌트 구조를 삽입합니다.
*   **React의 작동 방식 (DOM 조작의 변화):**
    *   과거 자바스크립트는 개발자가 직접 DOM 요소를 찾고, 생성하고, 변경하는 '명령적(Imperative)' 방식을 사용했습니다.
    *   반면 React는 "나는 이 화면에 이런 구조가 필요하다"라고 선언만 하면(`Declarative`), 내부적으로 필요한 모든 요소 관리와 업데이트를 책임지게 합니다. (Virtual DOM 개념 활용)
*   **주요 프로젝트 구성 요소:**
    *   **컴포넌트(Component):** 재사용 가능한 UI 조각을 의미합니다. (예: 버튼, 카드 섹션 등). React 개발의 기본 단위입니다.
    *   **`package.json`:** 프로젝트가 의존하고 있는 라이브러리 목록(dependencies)과 스크립트 명령들(`npm run dev`, `npm install`)이 정의되어 있는 핵심 설정 파일입니다.
        *   개발에 필요한 외부 라이브러리를 여기에 추가해야 합니다.
    *   **실행 과정:**
        1.  `cd my-react-app`으로 프로젝트 디렉토리 이동.
        2.  `npm install`: `package.json`에 명시된 모든 의존성(라이브러리)들을 다운로드하여 `node_modules` 폴더를 생성합니다. (실제 모듈 설치 단계).
        3.  `npm run dev`: 개발 서버를 실행하여 브라우저에서 화면을 확인할 수 있게 합니다.

## 4. React 핵심 개념과 개발 도구 정리

*   **컴포넌트 기반 아키텍처:**
    *   전체 애플리케이션을 작고 독립적인 여러 컴포넌트로 나누어 구성하는 방식입니다.
    *   복잡한 앱도 작은 컴포넌트들을 마치 레고처럼 조립하듯이 만들 수 있어 개발이 체계적이고 유지보수가 용이합니다.
*   **컴포넌트의 데이터 흐름:**
    *   모든 컴포넌트는 상태(State)와 속성(Props)을 통해 데이터를 주고받습니다.
    *   데이터 변경에 따라 React가 자동으로 화면을 업데이트해 줍니다.
*   **개발 도구의 역할 (Babel과 Vite):**
    *   **Babel:** 자바스크립트 문법은 시대에 따라 계속 발전하기 때문에, 개발자가 최신 기능을 사용해도 구형 브라우저에서도 정상적으로 작동할 수 있도록 **최신 코드를 표준화된 코드로 변환**해주는 역할을 합니다.
    *   **Vite:** 프로젝트 초기 설정부터 빌드 과정까지 전반적인 개발 과정을 빠르고 간결하게 처리하여 복잡성을 줄여줍니다.

1. 리액트 JSX 이해하기: 구조 및 규칙
2. 컴포넌트 기초 다지기: 정의와 사용 (Component Definition & Composition)
3. 데이터 전달 원리 학습: Props를 이용한 정보 흐름 (Props)
4. 고급 컴포넌트 패턴: 자식 요소 처리와 렌더링 (Children)

## 1. 리액트 JSX 이해하기: 구조 및 규칙
- **JSX란 무엇인가?**
    - HTML 코드처럼 보이지만, 실제로는 JavaScript 문법을 확장한 형태이다.
    - 컴포넌트를 정의할 때 사용되는 구문이며, 자바스크립트 코드를 직관적으로 작성할 수 있게 돕는다.
- **JSX의 특징 및 규칙:**
    - **JavaScript 통합 가능성:** JSX 내부에서는 `{}` 중괄호 문법을 사용하여 변수나 어떤 종류의 JavaScript 코드(변수, 계산식 등)를 포함시킬 수 있다.
    - **속성명 (Attributes):** HTML과 유사하지만, 클래스 이름은 `class` 대신 **`className`**을 사용하며, 속성은 주로 카멜 케이스(camelCase)를 따른다.
    - **닫는 태그의 강제성:** JSX 문법은 XML 기반이므로, 모든 HTML 태그는 반드시 닫아주어야 한다 (예: `<img />`, `<div>...</div>`). 이는 브라우저가 유연하게 해석하는 HTML보다 더 엄격한 규칙이다.
    - **반환 요소 처리:** 컴포넌트 함수에서 여러 개의 요소를 반환할 때는, 반드시 하나의 부모 태그(Parent Element)로 감싸줘야 한다.

## 2. 컴포넌트 기초 다지기: 정의와 사용 (Component Definition & Composition)
- **컴포넌트의 개념과 작성:**
    - 웹 화면을 독립적으로 재사용 가능한 단위로 분리하는 것을 의미한다. (예: Header, Welcome 등)
    - 일반적으로 함수형 컴포넌트로 만드며, 이 함수를 통해 UI(JSX)가 반환된다.
    - **관례:** 컴포넌트 이름은 항상 첫 글자를 대문자로 작성하는 것이 일반적인 관례이다.
    - **구현 방식:** `function` 키워드를 사용하거나 화살표 함수(Arrow Function) 문법을 사용하여 정의할 수 있으며, 기능적으로는 동일하다.
    - **필수 절차:** 컴포넌트는 반드시 모듈 시스템을 통해 외부에서 사용할 수 있도록 기본 내보내기(`export default`)가 되어야 한다.
- **컴포넌트 조립 (Composition):**
    - 하나의 화면은 여러 개의 작은 컴포넌트를 가져와 조립(Assembly)하여 구성한다.
    - 부모 컴포넌트는 자식 컴포넌트를 `<ChildComponent />` 형태로 불러와 사용한다.
    - 이 과정에서 `import`는 해당 컴포넌트가 외부에 `export` 되어 있음을 명시적으로 알려주는 필수 단계이다.

## 3. 데이터 전달 원리 학습: Props를 이용한 정보 흐름 (Props)
- **Props의 역할:**
    - 부모 컴포넌트(Parent Component)가 자식 컴포넌트(Child Component)에게 데이터를 전달하는 수단이자 메커니즘이다.
    - *주의사항:* 데이터 흐름은 기본적으로 **단방향**이다 (부모 $\rightarrow$ 자식). 자식이 스스로 부모의 상태를 변경할 수는 없다.
- **Props 사용 방법:**
    - **전달 (Parent):** 부모 컴포넌트가 자식 태그에 속성(Attribute)처럼 값을 넘겨준다. (예: `<ChildComponent name="값" age={숫자} />`)
    - **받기 (Child):** 자식 컴포넌트는 전달받은 데이터를 인자로 받는다.
        1.  **객체 구조분해 할당:** 받은 props 객체에서 필요한 값만 깔끔하게 추출하여 사용하는 것이 가장 효율적이다. (`const ChildComponent = ({ name, age }) => {...}`)
    - **데이터 타입 지원:** 단순히 문자열뿐 아니라 숫자 같은 JavaScript 데이터 타입 역시 `{}`를 이용해 전달할 수 있다.
- **Props와 Context API의 필요성 (배경 설명):**
    - 데이터를 가장 깊은 자식 컴포넌트까지 내려줄 때, 중간 단계의 여러 부모 컴포넌트를 거쳐야 하는 경우(Prop Drilling)가 발생한다. 이는 비효율적이다.
    - 이러한 구조를 해결하기 위해 Context API나 상태 관리 라이브러리 등이 존재하며, 값을 전역적으로 공유할 수 있도록 돕는다.

## 4. 고급 컴포넌트 패턴: 자식 요소 처리와 렌더링 (Children)
- **컴포지션의 확장:**
    - 일반적인 Props는 이름이 정해진 특정 데이터(예: `name`, `age`)를 받아 전달하는 방식이다.
    - 하지만 때로는 **누가, 몇 개나**, 어떤 내용을 자식 컴포넌트로 포함시킬지 미리 알기 어려울 수 있다. (예: 리스트 형태로 여러 개의 카드를 포함할 경우)
- **`props.children`의 활용:**
    - 부모 컴포넌트가 그 안에 들어오는 모든 자식 콘텐츠(Child Content)를 담을 수 있는 '자리' 역할을 할 때 사용한다.
    - `children`은 특별한 속성 이름으로, 자바스크립트 엔진이 해당 태그 사이에 위치한 *모든* JSX 요소들을 자동으로 묶어서 부모 컴포넌트로 전달해준다.
    - **사용 방법:** 부모 컴포넌트의 리턴부에서 `{props.children}`을 사용하여 동적으로 들어온 모든 요소를 렌더링할 수 있다.
- **개념적 이해:**
    - 이 패턴은 *컴포넌트를 위한 컨테이너(Wrapper)*를 만들 때 유용하며, 자식 컴포넌트가 어떤 것이든 관계없이 재사용 가능한 구조를 만드는 핵심 원리이다.

## 1. Props를 활용한 컴포넌트 간 데이터 전달 및 스타일링
(기본 원리)
- **데이터 흐름:** 부모 컴포넌트는 자식 컴포넌트를 호출할 때 데이터를 '속성값(Props)' 형태로 전달합니다. (단방향 데이터 흐름)
- **사용 예시:** 단순히 값(예: `text`)을 넘어 보내는 것 외에도, 스타일 값이나 컬러 정보 등 복합적인 객체 구조의 데이터도 전달하여 자식 컴포넌트의 모양과 동작에 영향을 줄 수 있습니다.
    - *(객체 활용)* CSS 스타일을 적용할 때도 속성값(Props) 형태로 `{border: '4px solid yellow', padding: '20px'}`와 같이 키-밸류 형태의 객체를 전달하여 사용합니다.
- **속성 구조 분해 할당:** Props를 받을 때, 필요한 데이터만 개별적으로 받아올 수 있습니다 (Destructuring).
    - 예: `const ChildComponent({ name, a })` 처럼 필요한 속성만 지정해서 받는 것이 가능하며, 이때 이름(key)의 일치 여부가 중요합니다.

## 2. 함수형 컴포넌트의 핵심: Hooks와 상태(State) 개념 학습
(이론적 이해)
- **Hooks란?** React에서 함수형 컴포넌트에 '상태 관리'나 '생명주기 기능' 등 복잡한 기능을 추가할 수 있게 해주는 특별한 내장 함수입니다.
    - *(핵심)* Hooks를 사용하면 클래스컴포넌트 없이도 상태 변화에 따라 UI가 업데이트되는 동적인 로직 구현이 가능합니다.
- **필수 기본 Hook:** React에서 반드시 알아야 할 가장 기본적인 세 가지 훅은 다음과 같습니다.
    1. `useState`: 컴포넌트 내부에서 변경 가능한 '상태(State)' 값을 관리할 때 사용합니다.
    2. `useEffect`: 부수 효과(Side Effect, 예: API 호출, 구독 설정 등)가 발생했을 때 특정 로직을 실행하도록 합니다.
    3. `useRef` (혹은 `useContext`): 주로 DOM 요소나 이전 상태 값에 접근할 때 사용됩니다.
- **`useState`의 역할 및 구조:**
    1. `useState`를 호출하면 React는 내부적으로 상태 값을 저장하고 관리합니다. 이로 인해 컴포넌트가 재렌더링(re-render)될 수 있는 근거가 마련됩니다.
    2. 이 함수는 항상 두 개의 요소를 가진 배열을 반환합니다: `[현재 값, 값을 업데이트하는 Setter 함수]`.
        - 예시: `const [count, setCount] = useState(0)`

## 3. `useState`를 이용한 카운터 실습과 리렌더링 원리 이해
(핵심 메커니즘)
- **상태 관리의 중요성:** JavaScript 내에서 일반 변수(`let count = 0`)로 값을 변경하는 것은 React가 추적하지 못합니다. 따라서 상태가 되게 하려면 반드시 `useState`를 이용해야 합니다.
- **불변성 및 업데이트:** 상태 값은 직접 수정해서는 안 됩니다 (예: `count++` 금지). 반드시 `setCount`와 같은 Setter 함수를 통해 값을 변경 요청해야 합니다.
- **리렌더링 원리 (가장 중요):**
    1. 사용자가 버튼을 클릭하여 `setCount(newValue)`를 호출하면, React는 이 상태의 변화를 감지합니다.
    2. React는 컴포넌트 함수 자체를 *처음부터 다시 실행*합니다 (Re-render).
    3. 컴포넌트가 재실행되면, 새롭게 계산된 카운트 값이 UI에 반영되어 화면이 업데이트됩니다.

## 4. 고급 상태 관리 응용 (예: 시간 계산 및 업데이트 로직)
(심화 활용)
- **시간 기반 로직 구현:** `useState`는 단순 숫자 외에도 날짜/시간 객체 등 복잡한 값을 저장하고 관리할 수 있습니다.
- **함수형 업데이트 (Functional Update):** 상태가 이전 값에 의존하여 변화해야 할 경우 (예: 타이머, 카운터 증가), 직접 새 값을 전달하기보다 이전 상태(`prevValue`)를 인자로 받아 로직을 실행하는 것이 안전하고 정확합니다.
    - 예: `setTimer(prevTime => { ... 로직 실행 ... })` 와 같이 작성하여 직전의 상태 값에 기반한 계산을 수행해야 합니다.
- **React Flow 이해:** React가 화면이 바뀌는 방식은 단순히 값을 변경하는 것이 아니라, *컴포넌트 함수 전체를 재호출*하여 새롭게 그림(렌더링) 그리는 과정임을 이해하는 것이 중요합니다.

## 1. useState를 활용한 기본 입력 필드(Text Input) 관리
*   **상태 주입의 목적:** 일반적인 HTML 입력창의 값을 React 상태로 연결하여 제어 가능한 컴포넌트로 만들어야 합니다. 이를 통해 사용자의 입력값에 따라 화면을 업데이트할 수 있습니다.
*   **작동 원리 (Controlled Component):**
    *   `<input>` 태그의 `value` 속성을 `useState`가 관리하는 상태 값과 연결합니다. (상태가 UI를 제어)
    *   사용자가 입력값을 변경하면, `onChange` 이벤트 핸들러가 실행됩니다.
    *   핸들러 내에서 이벤트 객체(`e`)의 `target.value` 값을 가져와 상태 업데이트 함수(setter)에 전달합니다. 이로써 React는 **상태 값이 변경되었다**고 인지하고 컴포넌트를 재렌더링합니다.

## 2. 리스트 형태로 데이터 출력하기 및 Key 속성 이해
*   **여러 항목 관리:** 여러 개의 이름 등 데이터를 상태로 유지해야 할 경우, `useState`의 초기값을 배열(`[]`)로 설정하여 목록을 관리할 수 있습니다.
*   **리스트 렌더링 (`map()` 사용):**
    *   배열 형태의 상태 값을 화면에 출력하려면 자바스크립트의 `map()` 함수를 사용하여 리스트 형태로 변환해야 합니다.
    *   각 항목은 반드시 적절한 HTML 태그로 감싸져야 합니다.
*   **불변성 원칙 (Immutable State):**
    *   상태 배열에 새로운 데이터를 추가하거나 수정할 때는 **기존 배열을 직접 변경(Mutation)**해서는 안 됩니다. React가 상태 변경을 감지하지 못하기 때문입니다.
    *   반드시 스프레드 연산자(`...`) 등을 사용하여 **새로운 배열을 생성**한 후, 이 새 배열로 상태를 업데이트해야 합니다. (`[...기존배열, 새데이터]`)
*   **`key` 속성 사용의 중요성:**
    *   `map()` 함수로 리스트를 렌더링할 때 각 요소에 고유하고 안정적인 `key` prop을 제공하는 것이 필수적입니다. (예: 데이터베이스의 ID나 인덱스)
    *   이 키는 React가 특정 항목이 추가, 삭제, 순서가 바뀌었을 때 어떤 요소를 재사용해야 할지 효율적으로 추적하여 성능 최적화를 돕습니다.

## 3. 커스텀 이벤트 핸들링: 키보드 이벤트 사용하기
*   **키 다운(Key Down) 이벤트:** 단순히 버튼 클릭에만 국한되지 않고, 특정 키가 눌렸을 때(예: Enter, Tab 등) 이벤트를 발생시켜 원하는 로직을 실행할 수 있습니다.
*   **이벤트 객체 활용:** Keydown 같은 모든 이벤트 핸들러는 이벤트를 인자로 받으며, 이를 통해 어떤 키가 눌렸는지(`e.key`) 등의 상세 정보를 얻어올 수 있습니다.

## 4. useState 핵심 원리 총정리 (불변성, 재렌더링 과정, 단방향 데이터 흐름)
*   **상태 값의 타입:** `useState`의 초기값으로는 문자열, 숫자 같은 기본 타입 외에도 객체(Object), 배열(Array), 심지어 함수도 들어갈 수 있습니다.
*   **핵심 원칙 1: 상태 변경 방법 (함수 사용 필수):**
    *   상태 값 자체가 바뀌는 것처럼 보이게 할 수 있지만, 실제로 **반드시 상태 업데이트 함수를 통해서 값을 바꿔야만** React가 이를 감지하고 재렌더링을 수행합니다.
    *   특히 객체나 배열처럼 복합적인 타입을 다룰 때는 직접 수정(Mutation)하지 않고, **새로운 참조를 가진 사본(Copy)**을 만들어 할당해야 합니다 (불변성 유지).
*   **핵심 원리 2: 재렌더링 과정 (Re-rendering):**
    *   개발자가 `setState` 함수를 호출하면 React는 상태가 변경되었다고 인지하고 컴포넌트 함수 전체를 다시 실행(재렌더링)합니다.
    *   이때 내부적으로 Virtual DOM을 이용하여 이전 상태와 새 상태의 가상 DOM을 비교("Diffing")한 후, **변경된 부분만** 실제 브라우저 DOM에 적용하여 성능을 최적화합니다.
*   **데이터 흐름 (Props):**
    *   React는 데이터가 항상 부모 컴포넌트에서 자식 컴포넌트로만 단방향으로 흐른다는 원칙(One-Way Data Flow)을 따릅니다.
    *   상태나 데이터를 하위 컴포넌트에 전달할 때는 `props`라는 속성을 통해 전달합니다.

## 1. JSX의 동작 원리 이해하기
*   **JSX란?** HTML처럼 생긴 문법이지만, 실제로는 JavaScript 코드가 동작하는 구문이다.
*   **동작 원리:** Spring에서 Thymeleaf 등을 이용해 서버 측에서 동적으로 화면을 생성하듯이, React 역시 자바스크립트 코드를 사용하여 HTML 구조를 동적으로 '생성'하고 리턴한다.
*   **핵심:** JSX 내부의 내용은 단순히 모양만 할 뿐, 근본적으로는 자바스크립트 코드이다.

## 2. 상태 관리와 Re-rendering: `useState` 활용
*   **HTML의 한계:** 일반적인 HTML은 한번 화면에 그려지면(렌더링) 그 값이 정적이라서 변할 수 없다.
*   **React의 해결책 (Re-rendering):** 데이터가 변경되었을 때 화면도 자동으로 업데이트되게 하려면, 기존 컴포넌트를 *전체적으로 다시 그려주는* 과정이 필요하다.
    *   React는 내부적으로 값이 바뀌는지 여부를 추적하고 있다가, 상태(State) 변화가 감지되면 해당 컴포넌트 함수를 재호출(재렌더링)하여 업데이트된 HTML을 얻어낸다.
*   **`useState`의 역할:** `useState`는 이러한 *상태값(State)*을 관리하기 위한 기본 훅(Hook)이다. 이 훅을 사용해야만 값이 변경되었을 때 화면이 실제로 바뀌는 '관찰 가능성'을 확보할 수 있다.

## 3. 컴포넌트 간 데이터 흐름: Props (Properties)
*   **Props의 정의:** 부모(Parent) 컴포넌트가 자식(Child) 컴포넌트로 데이터를 전달하는 값 또는 속성을 의미한다.
*   **핵심 원칙 - 단방향 흐름:** Props는 반드시 **부모 $\to$ 자식 방향(단방향)**으로만 데이터가 흐른다.
    *   자식은 부모의 Props를 받아 사용할 수 있지만, 스스로 임의로 상위 컴포넌트의 상태를 변경할 수는 없다.
    *   **주의:** 데이터를 전달하려면 반드시 계층 구조를 거쳐야 한다 (예: `Root` $\to$ `List` $\to$ `Item` 순으로 값을 전달해야 한다).

## 4. 데이터 전달 방식 심화 및 구조 분해
*   **데이터 흐름의 복잡성과 대안:** 실제 웹 개발에서는 컨트롤러 $\to$ 서비스 $\to$ 리포지토리와 같이 여러 레이어를 거치며 데이터를 전달하는 과정이 필수적이다 (전달 $\to$ 전달). 이 반복적인 과정은 코드를 번거롭게 만든다.
*   **Context API의 활용 (간접 설명):** 복잡한 계층 구조에서 무분별하게 Props를 계속 내려주는 것을 방지하고, 전역적으로 필요한 값을 효율적으로 관리하는 방법이 존재한다.
*   **Props 사용 실습:** 컴포넌트 간에 객체 형태로 데이터를 전달받을 때는 이를 **구조 분해 할당(Destructuring)**을 이용해 구조화된 방식으로 받는 것이 일반적이다.
*   **함수 이벤트 전달 (Key Concept):** Props를 통해 단순한 데이터 값뿐만 아니라, **실행할 수 있는 함수 자체**도 자식 컴포넌트로 넘겨줄 수 있다. 이는 부모에서 정의된 로직을 자식이 트리거하도록 하는 방식이다.

## 5. 애플리케이션 구조 설계 및 마무리
*   **컴포넌트 분리의 필요성:** 프로그램이 복잡해지고 기능(로직)이 다양해지면, 하나의 컴포넌트에 모든 것을 넣기보다 재사용성을 위해 **독자적인 기능을 가진 작은 단위의 컴포넌트로 분리**하는 것이 효율적이다.
*   **렌더링 프로세스 (React Lifecycle):**
    *   웹페이지 요청이 들어오면 인덱스 페이지가 동작하고, JavaScript가 메모리 내 `Root` 요소를 찾아 초기 컴포넌트(예: App Component)를 렌더링한다.
    *   컴포넌트의 시작 지점 로그를 찍어보면, 언제 로딩되고 실행되는지 **React의 라이프 사이클**을 이해하는 데 도움이 된다.
*   **최종 정리 및 학습 목표:** React 개발 시 가장 기본적으로 숙지하고 있어야 할 핵심 주제는 다음과 같다.
    1.  `Props`: 컴포넌트 간 단방향 데이터 전달 방법.
    2.  `useState`: 상태를 관리하여 변화가 발생했을 때 UI(화면)를 다시 그려내는 메커니즘 이해.
