## 1. React 학습 전 필수 JavaScript 문법 복습의 필요성
- **배경 지식의 중요성:** 스프링 개발 과정에서 자바 기본 문법(람다식, 스트림, 인터페이스 등)이 어렵게 느껴지는 것처럼, React도 결국 JavaScript 기반입니다. 따라서 JS 문법이 헷갈리면 React 학습 자체가 어려울 수 있습니다.
- **학습 목표 설정:** 이번 시간에는 당장 필요한 핵심 JS 문법들만을 골라 복습함으로써, React를 공부할 때 문법적인 혼란을 최소화하고 개념에 집중하는 것을 목표로 합니다.
- **기본 컴포넌트 이해:** React의 컴포넌트는 HTML의 박스처럼 재사용 가능한 단위이며, 이는 결국 하나의 함수(Function) 형태로 정의됩니다. 따라서 자바스크립트의 기본 함수 구조를 잘 이해해야 합니다.

## 2. 함수형 컴포넌트와 Modern JS 특징 이해하기
- **React Component의 작동 원리:** React에서 컴포넌트를 만드는 방식은 클래스 기반이 아닌, 순수 JavaScript 함수(Function)를 사용하여 구현됩니다. (함수형 컴포넌트)
- **필요한 핵심 문법 리스트:** React 개발에 자주 사용되므로 미리 복습해야 할 주요 JS 문법들입니다.
    *   **구조 분해 할당 (Destructuring):** 객체의 속성이나 배열의 요소를 쉽게 값으로 가져와 사용할 때 유용하게 쓰이며, 컴포넌트 Props 처리 시 많이 활용됩니다.
    *   **전개 구문 (Spread Operator, `...`):** 배열 또는 객체를 복사하거나 요소들을 나열할 때 사용합니다.
    *   **ES6 모듈 시스템:** `export`와 `import` 문법을 사용하여 코드를 구조적으로 분리하고 필요한 모듈만 가져다 쓸 수 있게 합니다.

## 3. JavaScript 함수의 핵심 개념 정리 및 실습
- **함수의 정의 방식 (Declaration vs. Expression):** JS에서는 함수를 선언하는 방식(Function Declaration)과 변수에 할당하는 방식(Function Expression, `const func = () => {}`)을 모두 사용할 수 있습니다.
- **⚠️ Overloading 불가:** JavaScript는 자바와 달리 함수의 오버로딩 기능을 지원하지 않습니다. 같은 이름의 함수가 중복 정의되면 가장 마지막에 정의된 내용만 유효하게 됩니다 (덮어쓰기). 따라서 변수나 상수에 할당하는 방식이 의도치 않은 문제를 방지하기에 더 안전합니다.
- **`this` 키워드와 `arguments`:** 함수의 내부에서 사용되는 `this`의 바인딩 규칙을 이해해야 합니다. 또한, 함수에 전달된 모든 인자를 배열 형태로 담아 사용할 수 있는 `arguments` 객체도 알아두어야 합니다.

## 4. 변수 스코프와 선언 방식 (Hoisting, Const) 심화 학습
- **JS는 1급 객체:** JavaScript에서 함수 자체도 일반적인 값처럼 객체(Object)로 취급됩니다. 따라서 함수를 변수나 상수에 할당하거나 매개변수로 전달할 수 있습니다.
- **호이스팅 (Hoisting):** 자바스크립트는 인터프리터 언어의 특성상 코드를 실행하기 전에 모든 선언을 먼저 메모리에 올리는 '호이스팅' 과정을 거칩니다. 이 때문에 나중에 정의된 함수를 위에서 호출해도 오류 없이 동작하는 것처럼 보입니다.
- **스코프 키워드별 특징:**
    *   **`var`:** 호이스팅이 발생합니다 (선언과 동시에 초기화되지 않음). 스코프 범위가 넓습니다.
    *   **`let` / `const`:** 블록 스코프를 가지며, 개발 시 안전성을 높여줍니다. 특히 `const`는 재할당을 막아주므로 변수를 선언하는 가장 권장되는 방식입니다.

## 5. 화살표 함수(Arrow Function)와 고급 문법 마스터
- **화살표 함수의 등장 배경:** 자바스크립트의 간결한 표현 방식을 위해 도입된 구문입니다 (자바의 람다식과 개념적으로 유사하나 구현 방식에 차이가 있음).
    *   **구문적 이점:** `function` 키워드 대신 화살표(`=>`)를 사용하므로 코드가 더 짧고 간결합니다. 개발자들이 선호하는 문법입니다.
- **화살표 함수의 특징:**
    *   **별도의 `this` 바인딩 문제 해결:** 일반 함수와 달리, 외부 스코프의 `this` 값을 그대로 상속받아 사용하므로 복잡한 `this` 문제를 피할 수 있습니다.
    *   **호이스팅 불가:** `const`나 `let`과 같이 변수에 할당되는 방식이므로, 선언되기 전에 호출하면 오류(`ReferenceError`)가 발생합니다.
- **리턴 값 처리 이해 (매우 중요):**
    *   **암시적 리턴 (Implicit Return):** 화살표 함수에서 본문 `{}`을 사용하지 않고 코드를 작성할 경우, 마지막 결과가 자동으로 반환됩니다. (코드가 짧고 단순할 때 유용)
    *   **명시적 리턴 (Explicit Return):** 중괄호 `{}`를 사용하여 복잡한 로직을 처리할 경우에는 반드시 `return` 키워드를 명시적으로 사용해야 합니다.

*(💡 **학습 조언:** 위에 언급된 다양한 JS 문법들이 섞여 있기 때문에, 직접 코딩하며 여러 번 테스트하고 사용하는 것이 가장 중요합니다. 강의에서 다룬 모든 문법들을 스스로 활용하여 작은 예제(함수)를 만들어보는 연습을 반복하는 것이 필요합니다.)*

## 1. JavaScript 객체 반환 시 주의 사항 (Return Syntax)
*   **객체 리터럴 반환 시 구문 오류 주의:** 함수에서 객체를 반환할 때, 단순히 중괄호 `{}`로 감싸면 해당 코드를 함수 본문(Block Scope)으로 해석하여 문제가 발생할 수 있다.
*   **올바른 방법:** 반드시 괄호 `()`를 사용하여 해당 블록을 함수가 수행하는 *값(Value)*으로 명시해야 오류 없이 객체가 반환된다. (예: `return ({ key: value })`)
*   **실무 적용:** 리액트 등 프런트엔드 개발 시 이 문법 구조의 차이를 명확히 이해하고 사용해야 컴파일 및 실행 오류를 방지할 수 있다.

## 2. 객체 속성 할당 및 간소화 문법
*   **속성 지정 방법:** 객체의 속성을 정의하거나 값을 할당할 때 `키: 값` 형태로 사용한다.
*   **간소화된 표기 (Short-hand):** 변수명이 객체의 키(Key) 이름과 완전히 일치하는 경우, `key: value` 대신 단순히 `변수명`만 사용하여도 동일한 효과를 얻을 수 있다. 이는 코드를 간결하게 만들지만, 원리적으로는 Key와 Variable이 같다는 전제하에 가능하다.
*   **코드 활용:** 이 문법은 React 등 실무에서 데이터를 다룰 때 매우 자주 사용되므로 개념을 숙지하는 것이 중요하다.

## 3. `this` 키워드와 스코프 이해하기
*   **기본 원칙 (Standard Function):** 일반 함수 내에서 `this`는 해당 함수가 호출된 컨텍스트(Context)를 가리킨다. (예: 객체의 메서드로 사용될 때, 그 객체 자체를 가리킴).
*   **화살표 함수 (`=>`)의 특징:** 화살표 함수는 자신이 선언된 상위 스코프(Lexical Scope)의 `this` 값을 그대로 물려받아 사용한다. 이는 일반 함수와 가장 큰 차이점이다.
*   **비동기 및 콜백 함수의 주의점 (Scope):** `setTimeout` 등 비동기로 실행되는 함수 내에서 `this`를 사용할 때, 해당 코드는 메인 스코프(Global Scope)가 아닌 별도의 컨텍스트에서 실행될 수 있으므로, 이때의 `this`가 무엇을 가리키는지 정확히 파악해야 한다.

## 4. 구조 분해 할당 (Destructuring Assignment)의 기본 원칙
*   **정의:** 객체나 배열 같은 데이터 구조로부터 필요한 값을 추출하여 새로운 변수에 한 번에 할당하는 문법이다. 코드를 간결하게 만들고 가독성을 높인다.
*   **객체 구조 분해 할당 (Object Destructuring):**
    *   **핵심 원칙:** 값의 **순서가 중요하지 않다**. 객체의 키(Key) 이름이 중요하다.
    *   **사용법:** 필요한 속성만 지정하여 추출할 수 있다. (`const { name, email } = user;`)
    *   **강점:** 원하는 필드만 정확히 추출할 수 있으며, 원본 객체에 해당 키가 없더라도 오류 없이 처리 가능하다 (해당 변수 값은 `undefined`가 된다).
*   **배열 구조 분해 할당 (Array Destructuring):**
    *   **핵심 원칙:** 값의 **순서가 매우 중요하다**. 배열 요소의 순서대로 값을 받는다.
    *   **구문 차이:** 배열을 다룰 때는 중괄호 `{}` 대신 대괄호 `[]`를 사용한다. (`const [a, b] = arr;`)

## 5. 중첩 객체 및 배열 구조 분해 할당 (Advanced Destructuring)
*   **중첩 객체 구조 분해:** 객체 안에 또 다른 객체가 들어있는 경우에도 점(`.`) 표기법을 사용하여 원하는 깊이의 값을 추출할 수 있다. (`const { user: { name, address } } = data;`)
*   **데이터 종류별 주의사항 요약:**
    *   **객체 (Object):** 키(Key) 이름 기반으로 접근하며, 순서는 자유롭다.
    *   **배열 (Array):** 인덱스 및 **순서**에 따라 값을 받는다.
*   **추가 팁 (기본값 설정):** 구조 분해 할당 시 존재하지 않는 속성에 대해 기본값을 지정하는 것도 가능하다. (`const { age = 20 } = user;`)

## 1. 객체 구조 분해 할당(Destructuring Assignment) 활용
*   **개념:** 객체나 배열에서 특정 속성(값)만 추출하여 변수로 편리하게 사용하는 문법입니다.
*   **활용 예시:** 함수를 호출하거나 인자를 전달할 때, 전체 객체를 받는 대신 필요한 키(key)를 지정하여 바로 값을 꺼내 사용할 수 있습니다. (예: `({ name, age })`와 같이 사용)
*   **목적:** 코드의 가독성을 높이고 코드를 간결하게 만들어줍니다.

## 2. React Hooks 이해 및 상태 관리 (`useState`)
*   **Hook 구조 분해:** `useState`와 같은 Hook을 사용할 때, 함수는 상태 값과 그 값을 업데이트하는 세터(Setter) 함수를 **배열 형태로 반환**합니다. 이 배열을 반드시 구조 분해하여 사용해야 합니다.
    *   **(예)** `const [state, setState] = useState(initialValue)`
        *   `state`: 현재의 상태 값이 담깁니다.
        *   `setState`: `state`를 변경할 수 있는 함수입니다.
*   **핵심 원리:** React가 화면을 다시 그려주기 위해서는 *상태가 바뀐 것*을 인식해야 합니다. Hook은 이 과정을 지원합니다.

## 3. 컴포넌트 설계와 자바스크립트 기본 문법 강화
*   **컴포넌트 개념:** 리액트에서 각 기능 단위는 '컴포넌트'로 생각할 수 있으며, 이는 마치 웹의 **박스 모델(Box Model)**과 같습니다.
    *   하나의 화면을 여러 개의 작은 컴포넌트들(작은 박스)을 조립하여 만들어내는 방식으로 코드가 구성됩니다 (Composition).
*   **전제 조건:** 리액트는 자바스크립트 문법입니다. 따라서 React가 어렵게 느껴진다면, 근본적으로 **자바스크립트의 기본 문법 지식**이 필수적입니다.

### ✅ 스프레드 연산자 (`...`) 활용 (ES6+)
*   **기능:** 객체나 배열을 펼쳐서(Spread) 다른 곳에 사용할 수 있게 해주는 매우 자주 사용되는 문법입니다.
*   **사용 예시:**
    *   **배열 복사/결합:** `[...array1, ...array2]` 처럼 두 배열의 내용을 합칠 때 사용합니다.
    *   **객체 확장 및 업데이트:** 기존 객체의 속성을 펼치면서 새로운 속성을 추가하거나 특정 속성을 덮어쓸 때 사용합니다.

## 4. React 상태 업데이트 원칙: 불변성 (Immutability) 유지
*   **최대 강조 사항:** 리액트에서 배열(Array)이나 객체(Object)와 같은 데이터를 수정할 때는 **절대로 기존의 값을 직접 변경해서는 안 됩니다.** (직접 수정 = Mutation 금지)
*   **원리 설명 (왜?):** 자바스크립트는 원시 타입이 아닌 배열이나 객체의 경우, '주소값'으로 존재합니다. 만약 데이터를 직접 수정할 경우, 리액트(React)가 이 *객체 자체의 주소가 변했는지*를 알 수 없기 때문에 화면 갱신을 하지 않습니다.
*   **올바른 방법 (불변성 유지):** 데이터에 변경이 생길 때는 **반드시 기존 데이터를 포함하는 '새로운 배열' 또는 '새로운 객체'를 만들어서 상태(State)로 교체**해줘야 합니다.

### 💡 핵심 패턴 구현을 위한 필수 메소드
*   **데이터 추가/삭제 시:** 새로운 배열을 만들어 기존 값과 새 값을 조합해야 합니다.
    *   `setTodos([...todos, newItem])`: 새 아이템 추가 시 (스프레드 연산자 사용)
*   **배열에서 데이터 삭제 시:** `Array.prototype.filter()`를 사용합니다. 필터는 조건을 만족하는 요소들만 담은 **새로운 배열을 반환**하므로 상태 업데이트에 적합합니다.
    *   `todos.filter(todo => todo.id !== idToDelete)`
*   **배열에서 데이터 값 수정 시:** `Array.prototype.map()`을 사용합니다. 맵 함수 역시 요소를 변경한 **새로운 배열을 반환**하며, 내부 로직에서 불변성을 유지하여 기존 속성은 스프레드 연산자로 복사하고 필요한 속성만 변경해줘야 합니다.
    *   `todos.map(todo => ({ ...todo, done: !todo.done }))`: 특정 속성(`done`)만 반대로 바꿔 새 객체를 생성합니다.

# 강의 요약

이 강의는 리액트(React) 개발에 필수적인 상태 관리 원칙과 자바스크립트 모듈 시스템(ES6 Modules)의 개념을 깊이 있게 다루고 있습니다. 특히, 데이터를 수정할 때 단순히 내용만 변경하는 것이 아니라 '새로운 객체 또는 배열'을 생성하여 불변성(Immutability)을 유지해야 하는 이유와 그 방법을 중점적으로 설명합니다.

---

## 목차
1. 리액트의 상태 관리 원칙 및 불변성 이해 (State Immutability)
2. 상태 업데이트를 위한 함수형 기법 (Array Methods 활용)
3. ES6 모듈 시스템: 코드의 분리와 재사용 (Import & Export)

---

## 1. 리액트의 상태 관리 원칙 및 불변성 이해
리액트에서 컴포넌트는 데이터(State)의 변화에 반응하여 화면을 다시 그립니다. 핵심은 '데이터가 바뀌었다'는 사실을 **리액트에게 인지**시키는 것입니다.

*   **핵심 개념: 새로운 개체 생성 (Immutability)**
    *   단순히 기존 배열이나 객체의 내용을 수정(예: `list.push()` 또는 `data.value = 'new'`)하는 방식은 **참조 주소(Reference Address) 자체가 바뀌지 않습니다.**
    *   리액트는 값이 변경되었는지 확인하기 위해 이 참조 주소를 비교하는데, 내용만 바뀐 경우 리액트가 변화를 인지하지 못하여 컴포넌트가 업데이트되지 않는 문제가 발생합니다. (Re-render 실패)
    *   **해결책:** 상태(State)를 변경할 때는 반드시 **새로운 배열이나 새로운 객체 자체를 생성**해야 합니다. 이렇게 해야 참조 주소가 바뀌고, 리액트는 이를 감지하여 컴포넌트를 재실행(Re-call)합니다.

*   **작동 원리 정리**
    *   컴포넌트가 화면을 그릴 때 (함수 호출), 이 함수는 현재의 상태(State)를 사용합니다.
    *   만약 데이터 값이 바뀌면, 리액트는 해당 컴포넌트를 다시 호출하여 새로운 화면을 그려야 합니다.
    *   리액트는 '상태'라는 변수의 **값**이 아닌 **참조 주소** 변화를 감지함으로써 업데이트 필요성을 판단합니다.

## 2. 상태 업데이트를 위한 함수형 기법 (Array Methods 활용)
데이터 구조(배열, 객체)의 불변성을 지키면서 상태를 업데이트하기 위해 내장 메서드들을 사용하는 것이 효과적입니다.

*   **필터링 (`filter`)**:
    *   특정 조건(`condition === true`)을 만족하는 요소들만 골라내어 **새로운 배열을 반환**합니다. (예: 목록에서 특정 항목 제외하기)
*   **매핑 (`map`)**:
    *   원래 배열의 모든 요소를 순회하며, 각 요소를 새로운 값으로 변형시킨 후 **새로운 형태의 배열을 반환**합니다. (예: 데이터 객체 구조 변경하기)
*   **업데이트 시 주의사항:**
    *   배열 내부의 특정 요소(객체)만 수정해야 할 경우에도 반드시 해당 객체 자체를 복사하고 필요한 속성만 덮어씌워야 합니다.
    *   이때 **스프레드 연산자 (`...`)**를 사용하여 기존 요소들을 새로운 배열/객체에 펼쳐주는 과정이 필수적입니다. (예: `{ ...originalObject, updatedProp: newValue }`)

## 3. ES6 모듈 시스템: 코드의 분리와 재사용 (Import & Export)
모듈(Module)은 코드를 기능별로 독립적인 파일 단위로 분리하여 관리하고, 필요한 곳에서 가져다 쓸 수 있도록 하는 표준 방식입니다. 이는 대규모 프로젝트를 구축하는 리액트와 같은 환경에서 필수적입니다.

*   **핵심 개념:** 재사용성 및 코드 구조화
    *   자바스크립트를 여러 파일로 나누어 코드를 모듈화하고, 이를 가져다 쓰는 것이 목표입니다.
*   **`export` (내보내기):**
    *   개발자가 '이 기능을 외부에서 사용하도록 허락합니다'라고 지정하는 키워드입니다.
    *   **Named Export:** 특정 이름으로 내보냅니다. (예: `export const PI = 3.14;`) -> 가져올 때 중괄호 `{}`와 이름을 명시해야 함.
    *   **Default Export:** 모듈의 기본값으로 지정합니다. (가장 대표적인 값 하나) -> 가져올 때 이름과 상관없이 사용 가능하며, `default` 키워드는 생략됨. (`export default MyComponent;`)

*   **`import` (가져오기):**
    *   다른 파일에 정의된 기능을 현재 파일로 불러와 사용하는 예약어입니다.
    *   **Named Import:** `{ }`를 사용하여 이름과 함께 가져옵니다. (예: `import { PI } from './utils';`)
    *   **Default Import:** 중괄호 없이 모듈 단위로 가져옵니다. (예: `import Calculator from './calculator';`)
    *   **별칭 사용 (`as`):** 같은 이름의 함수나 값을 가져와야 할 때 충돌을 방지하기 위해 별명을 붙일 수 있습니다. (예: `import { add as stringAdd } from 'string-utils';`)

## 1. 모듈 시스템 이해 및 실습 (Export/Import)
- **모듈화의 필요성:** 사용했던 함수, 상수 등의 코드들을 하나의 파일(모듈)로 묶어 관리하는 것이 중요합니다.
- **워크플로우 실습:** 코드를 재사용하기 위해 특정 파일을 '내보내기(export)'하고, 다른 파일에서 이를 '가져오기(import)'하여 사용하는 과정을 직접 실습해봅니다.
- **Export 종류 이해:** `default`를 사용하여 내보내는 방식과 일반적인 `export`의 차이점을 정확히 이해해야 합니다.
- **React에서의 적용:** React 컴포넌트나 유틸리티 함수 등을 구성할 때 모듈 시스템을 활용하여 관리합니다.

## 2. 배열 조작을 위한 핵심 메서드 학습 (Map, Filter, Reduce 등)
배열 내장 메서드는 데이터를 효율적으로 가공하고 변형하는 데 필수적입니다.

*   **`map()`:**
    *   원래 배열의 각 요소를 기반으로 **새로운 리스트(배열)**를 생성하여 반환할 때 사용합니다. (예: 유저 객체 배열에서 이름만 추출하여 새로운 배열 만들기).
    *   데이터 구조 변환에 가장 많이 사용됩니다.
*   **`filter()`:**
    *   특정 **조건을 만족하는 요소들만 골라내어** 새로운 배열로 반환합니다. (예: 숫자 배열 중 짝수만 남기기, 사용자 객체 중 나이가 25세 이상인 사람만 걸러내기).
*   **`find()` / `findIndex()`:**
    *   `find()`: 조건에 맞는 **첫 번째 요소 자체(Object)**를 찾아 반환합니다.
    *   `findIndex()`: 조건에 맞는 첫 번째 요소의 **실제 인덱스 값(Number)**을 반환합니다.
*   **`some()` / `every()`:** (조건 검증 메서드)
    *   `some()`: 배열 요소 중 **하나라도** 주어진 조건을 만족하면 `true`를 반환합니다.
    *   `every()`: 배열의 **모든 요소가** 주어진 조건을 모두 만족해야만 `true`를 반환합니다.
*   **`reduce()`:**
    *   배열의 모든 요소를 순회하며 **값을 누적(Accumulate)**하여 최종적인 단일 결과값(숫자, 객체 등)을 도출할 때 사용합니다. 초기값을 설정하고 반복적으로 계산하는 원리를 이해해야 합니다.

## 3. 자바스크립트의 고급 문법과 안정성 강화 기법
코드의 가독성을 높이고 오류를 방지하기 위해 최신 문법들을 사용하는 것이 중요합니다.

*   **삼항 연산자 (Ternary Operator):**
    *   `조건 ? 참일 때 값 : 거짓일 때 값` 형태로, `if-else` 구문을 매우 간결하게 대체하여 사용됩니다. (예: 로그인 여부에 따라 환영 메시지를 다르게 출력).
*   **논리 단축 평가 (Logical Short-Circuiting):**
    *   `&&` 연산자: **앞의 조건식과 뒤의 조건식이 모두 `true`일 때만** 최종 결과가 `true`가 됩니다.
    *   `||` 연산자: 두 값 중 **하나라도 `true`일 경우** 그 값을 반환합니다. (즉, 왼쪽 값이 falsy하면 오른쪽 값을 사용).
*   **옵셔널 체이닝 (`?.` - Optional Chaining):**
    *   객체 속성이나 메서드 호출 시 해당 값이 `null` 또는 `undefined`인지 확인하고 안전하게 접근할 수 있게 합니다.
    *   기존에는 `if else` 문을 사용하여 오류를 방지해야 했으나, 이 기법을 사용하면 **오류 발생 없이 코드를 간결화**하여 Null Pointer Exception 등의 위험을 크게 줄여줍니다.
*   **핵심 지식 비교 (JS Typing):**
    *   자바스크립트에서 `null`, `undefined` 외에도 숫자 0이나 빈 문자열(`''`) 같은 값들이 **'Falsy(가짜)'**로 처리될 수 있어 혼란을 야기합니다.
    *   문법적인 안전성을 높이기 위해 물음표 문법 (`??`)과 같은 발전된 기법들을 학습하여, 기본 타입의 `falsy` 판별 기준 차이를 명확히 이해하는 것이 중요합니다.

**💡 핵심 정리:** 리액트 자체가 자바스크립트를 기반으로 하므로, 프레임워크 사용에 앞서 위에서 다룬 고급 자바스크립트 문법과 개념들을 깊이 있게 학습해야 코드 구조를 정확하게 파악할 수 있습니다.
