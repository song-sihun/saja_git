## 1. AOP 소개 및 필요성
- **AOP(Aspect-Oriented Programming)란?**
    - 스프링의 핵심 기술 중 하나로, 시스템의 동작 원리상 내부적으로 사용하는 기술(IOC, DI 등과 유사)이다.
    - 객체지향 프로그래밍(OOP)을 보조하여 코드를 더 객체지향적으로 설계할 수 있도록 돕는 패러다임이다.
- **AOP의 등장 배경 (문제 정의):**
    - 로깅(Logging), 트랜잭션 처리, 보안 검증(Authentication), 캐싱 등은 특정 비즈니스 기능(핵심 로직)에서만 사용되는 것이 아니라, 여러 다른 곳(전체 모듈)에서 공통적으로 필요로 하는 기능들이다.
    - 만약 이러한 공통 기능을 비즈니스 코드 안에 직접 작성하게 되면, 코드가 장황해지고(코드 중복 증가), 유지보수가 어렵고, 기능을 추가할 때마다 많은 부분을 수정해야 하는 문제(점진적 수정의 어려움)가 발생한다.
- **AOP를 통한 해결:**
    - AOP는 이러한 공통적으로 반복되는 코드를 별도의 모듈로 분리하여, 핵심 비즈니스 로직 코드를 건드리지 않고도 해당 기능을 실행할 수 있게 한다. (예: `@Transactional` 어노테이션 하나만 붙여도 트랜잭션 시작/커밋/롤백 코드가 자동으로 삽입됨)

## 2. AOP의 핵심 원리: 횡단 관심사의 분리
- **관심사 분리 (Separation of Concerns):**
    - AOP의 가장 핵심 가치이며 목적이다.
    - **핵심 로직 (Core Logic):** 서비스가 처리해야 하는 본질적인 비즈니스 규칙 (예: 회원가입 시, 이 계좌로 송금한다).
    - **부가 기능 (Cross-cutting Concerns, 횡단 관심사):** 핵심 로직을 안전하게 만들거나 보조하는 기능 (예: 트랜잭션 관리, 로그 기록, 보안 처리).
    - AOP는 이 두 가지 관심사를 분리하여, 개발자가 오직 핵심 비즈니스 로직에만 집중할 수 있게 한다.
- **장점:**
    - **유지보수성 향상:** 공통 로직을 한 곳에서 수정하면 모든 곳에 반영된다.
    - **재사용성 극대화:** 해당 코드를 여러 모듈의 어디에서든 재사용할 수 있다.
    - **코드 간결화:** 비즈니스 코드가 복잡한 공통 코드로 오염되는 것을 막아준다.

## 3. AOP의 주요 용어 정리
- AOP는 개념이 중요하므로, 다음 용어들을 익숙하게 이해하는 것이 필수적이다.
    - **횡단 관심사 (Cross-cutting Concern):** 특정 비즈니스 로직에 국한되지 않고 시스템 전반에 걸쳐 나타나는 공통적인 관심사 (예: 로깅, 트랜잭션).
    - **Advice (어드바이스):** 실제로 삽입되는 '코드 조각' 자체를 의미한다. (예: 로그를 남기는 코드).
    - **Pointcut (포인트컷):** Advice가 **어디서** 실행될지를 정의하는 규칙이다. (예: `User` 클래스의 모든 메서드가 실행될 때).
    - **JoinPoint (조인 포인트):** Pointcut 규칙에 의해 실제로 '적용될 수 있는 지점'을 의미한다.
    - **Aspect (어스팩트):** Advice(실제 코드)와 Pointcut(적용 위치)의 조합을 통칭한다. 즉, "어디서 어떤 코드를 넣을 것인지"를 정의하는 단위다.
    - **Target (타겟):** 실제 핵심 비즈니스 로직이 담겨있는 대상 객체를 말한다.
    - **Weaving (위빙):** 실제 코드가 실행될 때, Aspect에 정의된 부가 기능 코드(Advice)를 가져와 Target의 코드와 엮어(포함시켜) 실행시키는 과정을 말한다.
    - **Proxy (프록시):** Spring AOP가 위빙을 구현하는 데 주로 사용하는 기술이다. AOP는 원본 객체를 가로채는 가상의 객체(프록시)를 생성하여 부가 기능을 삽입한다.

## 4. AOP 동작 원리 및 결론
- **AOP의 핵심 동작 원리:**
    - 개발자가 직접 트랜잭션 시작/커밋/롤백 등의 코드를 붙이는 대신, 어노테이션(예: `@Transactional`)만 붙인다.
    - Spring Framework는 내부적으로 AOP 메커니즘(프록시)을 이용해 해당 메서드가 호출되는 시점(JoinPoint)에 부가 기능 코드(Advice)를 자동적으로 삽입(Weaving)하여 처리해준다.
- **정리 및 심화 학습:**
    - AOP의 동작 원리를 이해하면, 코드가 복잡하게 섞여 보이는 현상을 "어, 저 부분이 AOP에 의해 트랜잭션 코드로 추가되는구나"라고 원리를 파악할 수 있게 된다.
    - 이 원리적 이해는 Spring의 복잡한 기술(AOP, 트랜잭션, 보안 등)을 학습하는 데 있어 가장 중요한 토대가 된다.

## 1. AOP의 필요성 및 개념 이해
- **배경:** 일반적인 코딩 방식에서는 트랜잭션 관리, 보안, 로깅 등의 기능이 비즈니스 로직(핵심 코드) 내에 직접 포함되는 경향이 있습니다.
- **문제점:** 이러한 기능(예: 트랜잭션 관련 코드)을 추가하거나 삭제할 경우, 실제 비즈니스 로직을 담당하는 메서드(`adUser`와 같은)를 직접 수정해야 합니다. 이는 코드의 유지보수성과 변경 용이성을 떨어뜨립니다.
- **AOP 도입의 목적:** AOP(Aspect-Oriented Programming)를 사용하면, 로깅이나 트랜잭션 처리 같은 **횡단 관심사(Cross-cutting Concerns)** 코드를 비즈니스 로직에서 분리하여 별도의 모듈로 관리할 수 있습니다.
- **결과:** 핵심 비즈니스 로직(도메인 로직) 코드를 전혀 수정하지 않고도, 로깅이나 보안 처리를 추가하거나 변경할 수 있어 **결합도를 낮추는** 데 매우 유리합니다.

## 2. Spring AOP 구현 실습 및 핵심 문법 학습
- **AOP의 원리:** AOP는 개발자가 코드를 직접 수정하는 대신, 특정 지점(Pointcut)에 '관심사'를 붙여서 동작하게 만듭니다.
- **구현 단계:**
    1. **Aspect 클래스 생성:** 로깅 등의 기능을 담당하는 `Aspect` 클래스를 별도로 만듭니다.
    2. **빈(Bean) 등록:** 이 `Aspect` 클래스도 스프링 컨텍스트가 인식할 수 있도록 `@Component` 어노테이션을 붙여 빈으로 등록해야 합니다.
    3. **로깅 추가:** 실제 메서드가 실행되는 지점에 로깅 코드를 추가하는 과정을 시뮬레이션하며 AOP의 동작 원리를 이해합니다.
- **AOP 핵심 문법 (애노테이션):** AOP가 동작할 시점과 범위를 지정하는 중요한 문법들입니다.
    *   **Pointcut (지점 지정):** 코드가 실행되는 특정 위치를 지정합니다.
    *   **Advice (처리 방식 지정):** 실제로 추가할 코드를 어떤 시점에 적용할지 결정합니다. 주요 유형은 다음과 같습니다.
        *   `@Before`: 메서드 실행 **전에** 특정 코드를 실행합니다.
        *   `@After`: 메서드 실행 **후에** 특정 코드를 실행합니다.
        *   (기타: `@Around`, `@AfterReturning` 등이 있으며, 실행 전후의 동작을 제어할 수 있습니다.)
    *   **Scope 지정 방법:**
        *   **클래스명 기반:** 특정 클래스(`UserDao`)의 메서드에만 적용하도록 지정합니다.
        *   **메서드명 기반:** 특정 메서드 이름(`addUser`)을 가진 메서드에만 적용하도록 지정합니다.
        *   **패턴 기반:** 특정 접두사(예: `*` 또는 `add*`)를 가진 메서드 전체에 적용하도록 지정합니다.
        *   **매개변수 타입 기반:** 메서드의 매개변수 타입(예: `Integer` 타입)을 기준으로 적용 지점을 결정할 수 있습니다.

## 3. AOP를 활용한 시스템 설계 및 결합도 개선
- **핵심 로직과 부가 기능 분리:**
    *   **서비스 계층 (Service Layer):** 시스템의 가장 핵심적인 비즈니스 로직이 위치해야 합니다. 이 부분은 AOP의 영향을 받아도 수정되지 않도록 보호하는 것이 중요합니다.
    *   **AOP 적용의 장점:** 로그 기록, 트랜잭션 관리(Transaction Management), 보안 검사 등의 기능은 AOP를 이용해 시스템 전반에 걸쳐 일관되게(횡단적으로) 추가할 수 있습니다.
- **결합도(Coupling) 감소:**
    *   서비스 로직과 부가 기능이 섞여 있을 때(높은 결합도), 수정할 때마다 여러 부분을 건드려야 합니다.
    *   AOP를 사용하면 각 관심사(로깅, 트랜잭션 등)가 독립적인 Aspect로 존재하여, 코드가 분리되고 각 부분이 상호 간에 의존하는 정도가 낮아집니다 (낮은 결합도).
- **결론:** AOP는 시스템을 모듈화하고, 핵심 비즈니스 로직만 깨끗하게 남겨두는 가장 효과적인 방법론 중 하나입니다.

## 1. AOP의 기본 개념 및 필요성
- **AOP(Aspect Oriented Programming) 정의:** 객체 지향 설계에서 비즈니스 로직(핵심 기능)과 무관하지만 반복적으로 필요한 부가 기능(로깅, 트랜잭션 처리 등)을 분리하여 구현하는 프로그래밍 기법.
- **문제 해결:** 기존 객체 지향 방식대로 코드를 수정하면(예: 로그를 추가) 핵심 비즈니스 로직 코드에 직접 영향을 주게 되어 유지보수가 어렵다.
- **AOP의 목표:** 핵심 비즈니스 로직 코드를 **단 한 줄도 건드리지 않고**, 프로그램의 특정 지점(Join Point)에 부가 기능을 주입(Weaving)하여 코드를 추가하는 것이 목표이다.
- **횡단 관심사(Cross-cutting Concern):** 로깅, 트랜잭션 관리, 보안 검증 등 특정 모듈에 국한되지 않고 시스템 전반에 걸쳐 필요로 하는 공통적인 관심사. AOP는 이러한 횡단 관심사를 분리하여 관리할 수 있게 한다.

## 2. AOP 구현의 핵심 요소 (Pointcut과 JoinPoint)
- **AOP 어드바이스(Advice):** 코드가 동작하는 특정 시점에 추가하는 부가 로직 조각 (예: `before`, `after` 등).
- **조인 포인트(JoinPoint):** 어드바이스가 실제로 삽입될 수 있는 지점. 즉, 어떤 메서드가 실행되는지 그 지점 자체를 의미한다.
- **포인트 컷(Pointcut):** 특정 종류의 조인 포인트를 지정하는 표현식. '어디서(Where)' 코드를 추가할지 규칙을 정의하는 역할을 한다.
    - **사용 방법:** `Execution`과 같은 클래스 이름과 메서드 이름을 조합하여 사용하며, `*` (모든 것)이나 `..` (패키지 깊이)와 같은 와일드카드 문자를 사용하여 규칙을 확장할 수 있다.
    - **핵심:** Pointcut은 단순히 메서드 이름만 지정하는 것을 넘어, 패키지명 전체나 특정 패턴에 맞는 모든 클래스/메서드에 걸쳐 동작하도록 정의할 수 있다.

## 3. 다양한 Advice 유형 이해 및 사용법
AOP는 메서드의 생애주기(Life Cycle)에 따라 다섯 가지 주요 어드바이스 유형을 제공한다.

### 🔹 `@Before`
- **동작 시점:** 실제 대상 메서드가 실행되기 **전**에 동작한다.
- **주요 활용:** 메서드 실행 전에 필요한 사전 검증이나 초기화 로직 추가.
- **강화 기능:** `JoinPoint` 객체를 받아 현재 실행되는 메서드 이름, 파라미터 값 등의 정보를 얻어낼 수 있다.

### 🔹 `@After`
- **동작 시점:** 대상 메서드가 종료된 **후**에 동작한다. (성공/실패와 무관)
- **주요 활용:** 자원 해제(Resource Cleanup) 등 항상 수행해야 하는 후처리 작업.

### 🔹 `@AfterReturning`
- **동작 시점:** 대상 메서드가 예외 없이 **정상적으로 리턴된 후**에 동작한다.
- **주요 활용:** 성공적으로 리턴된 값(Return Value)을 받아 후속 처리를 하거나 로깅하는 경우.
- **특징:** 메서드가 리턴 값을 가지고 돌아왔을 때만 실행된다.

### 🔹 `@AfterThrowing`
- **동작 시점:** 대상 메서드 실행 중 **예외(Exception)**가 발생했을 때 동작한다.
- **주요 활용:** 예외가 발생했을 때 복구 로직 수행, 로그 기록 등.
- **주의:** 예외가 발생하지 않으면 실행되지 않는다.

### 🔹 `@Around`
- **동작 시점:** 대상 메서드를 **전체적으로 감싸서(Wrapping)** 실행된다.
- **특징:** `ProceedingJoinPoint`를 사용하여 실제 메서드를 호출할지 여부, 실행 순서, 심지어 리턴 값을 가로채서 강제로 변경할 수 있다.
- **활용:** 트랜잭션 관리(Transaction Management)처럼 핵심 로직의 시작부터 끝까지 전체 흐름을 통제해야 하는 상황에 가장 적합하다.
- **흐름 제어:** `@Around`가 가장 먼저 실행되며, 모든 어드바이스 중 가장 높은 제어권을 갖는다.

## 4. AOP의 동작 원리 및 설계적 의미
- **Advice 실행 순서 (순서 제어):** 여러 개의 어드바이스가 하나의 포인트 컷에 걸쳐 정의될 경우, `@Order` 어노테이션 등을 사용하여 누가 먼저 실행될지 **우선순위(Order)**를 지정할 수 있다.
- **`@Around`의 심화:**
    - `@Around`는 메서드 전체를 감싸는 '필터' 역할에 비유되며, 요청을 받아 실행하고 응답을 다시 보내는 과정을 모두 통제할 수 있다.
    - `ProceedingJoinPoint`를 통해 실제 타겟 메서드를 강제로 호출하고(proceed), 그 반환 값(Return Value)을 받아와서 원하는 형태로 조작할 수 있다.
- **AOP의 가치:**
    - AOP는 개발자가 핵심 비즈니스 로직(도메인 로직)에 집중할 수 있도록, 반복적이고 부가적인 시스템 기능을 분리하고 자동화할 수 있게 도와준다.
    - 이는 객체 지향 설계의 발전 형태 중 하나로, 유지보수성과 확장성을 극대화하는 데 기여한다.

## 1. AOP 실습 및 복습 가이드
- **자기 주도 학습 권장:** 고급 실수 배제와 같은 주제는 예제가 충분히 제공되므로, 수강생들이 실습을 진행해 볼 수 있습니다.
- **복습 방법:** 시간이 있다면 기초적인 내용을 정리하면서 몇 가지 예제들을 함께 보며 AOP를 다시 한번 정리해 보는 것이 좋습니다.

## 2. AOP의 핵심 이해 목표 설정 (개념적 이해의 중요성)
- **초보 학습자 가이드:** AOP의 활용 방법이나 기술적인 디테일(구현 방법)까지 모두 완벽하게 알 필요는 없습니다.
- **중요한 목표:** AOP가 '이런 방식으로 동작할 수 있는 기술이 있다'라는 것을 이해하는 데 집중하는 것이 중요합니다.
- **사례:** 초기 교육 과정에서는 AOP를 아예 다루지 않고 지나가기도 합니다. 따라서 사용 방법을 디테일하게 아는 것보다, 그 존재 자체를 아는 것이 더 중요합니다.

## 3. AOP가 제공하는 근본적인 가치와 역할
- **AOP가 필요한 이유 (문제 제기):** AOP가 없었을 때, 개발자는 실제 비즈니스 메서드에 트랜잭션 처리나 로깅 등의 공통 로직(프록시 코드)을 수작업으로 추가해야 했습니다.
- **AOP의 기능 (핵심):** AOP를 사용하면 실제 구현한 비즈니스 로직(핵심 코드)을 **단 한 줄도 수정하거나 추가할 필요가 없음에도 불구하고,** 트랜잭션 처리나 보안 로직 같은 공통 기능을 자동으로 삽입하거나 포함하여 동작시킬 수 있게 됩니다.
- **이해의 핵심:** 본인이 작성한 코드에 아무것도 건드리지 않았는데도, 외부 기술(Aspect)의 코드가 자동으로 포함되어 실행되는 메커니즘을 이해하는 것이 AOP 학습의 가장 중요한 핵심입니다.
- **결론:** AOP가 무엇이며, **어떤 방식으로 동작하는지(개념)**를 이해하는 것에 목표를 두는 것이 가장 바람직합니다.
